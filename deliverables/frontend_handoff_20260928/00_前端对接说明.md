# 短波/超短波智能规划系统前端对接资料包

交付日期：2026-09-28

## 1. 使用范围

本资料包用于外包前端开展页面开发、地图图层开发、字段对接和第一轮接口联调。

包内节点、任务、频率、拓扑、链路状态和干扰数据主要为合成测试数据，只能作为联调数据使用，不代表最终业务部署数据。DEM、地物和道路为已预处理数据，其来源及授权状态见本文件第 7 节。

## 2. 目录说明

| 目录 | 内容 | 前端用途 |
|---|---|---|
| `01_接口与算法文档/` | 接口协议、数据字典、模块关系和算法输入输出说明 | 确认字段、枚举、交互流程和展示内容 |
| `02_接口样例/` | JSON 请求与响应样例 | Mock 数据和接口联调 |

## 3. 统一数据约定

- 字符编码：UTF-8。
- 接口数据格式：JSON。
- 地理坐标系：WGS 84（EPSG:4326）。
- 坐标顺序：经度在前、纬度在后，即 `[lon, lat]`。
- 时间格式：ISO 8601，包含时区。
- CSV 缺失值：空字符串。
- JSON 缺失值：`null`。
- 布尔值：`true`、`false`。
- 枚举值按数据字典中的英文编码传输，中文名称仅用于界面显示。
- 频率单位：kHz；功率单位：dBm；距离单位：m；时延单位：ms。

详细字段定义以 `01_接口与算法文档/01_数据字典.md` 为准。

## 4. 接口联调约定

- API 基础路径：`/api/v1`。
- 统一响应结构：`code`、`message`、`data`、`request_id`。
- 是否成功以业务字段 `code` 为准，不能只判断 HTTP 状态码。
- 耗时算法使用异步任务模式：提交后取得 `task_id`，再查询任务状态。
- 任务状态：`PENDING`、`RUNNING`、`SUCCESS`、`FAILED`、`CANCELLED`。
- 任务进度取值范围：0 到 1。
- 前端建议每 2 秒轮询一次，最终频率待双方联调确认。
- 覆盖结果建议按 GeoJSON 等值线与 PNG 栅格叠加层展示。

接口的请求字段、响应字段和错误码以 `01_接口与算法文档/03_接口文档.md` 为准。

## 5. 当前算法接口范围

当前设计及代码中包括以下接口组：

- 候选部署点：`POST /api/v1/plan/candidate-sites`
- 移动电台部署：`POST /api/v1/plan/deployment`
- 覆盖计算：`POST /api/v1/plan/coverage`
- 路由规划：`POST /api/v1/plan/route`
- 频率分配：`POST /api/v1/plan/frequency`
- 电台参数规划：`POST /api/v1/plan/radio-params`
- 方案冲突检查：`POST /api/v1/plan/check`
- 多目标组网优化：`POST /api/v1/plan/network-optimize`
- 干扰分析与措施采纳：`POST /api/v1/interference/analyze`、`POST /api/v1/interference/adopt`
- 全流程规划：`POST /api/v1/plan/sr4-flow`
- 异步任务查询：`GET /api/v1/plan/tasks/{task_id}`
- 设备、天线、频率和参数预设资源查询：`GET /api/v1/resource/*`
- 方案列表、详情、比较、确认和导出：`/api/v1/plans*`

`02_接口样例/` 当前只提供候选点、路由、频率分配和故障诊断四组请求/响应示例。其他接口应以接口文档为准，完整样例仍需后续补齐。

## 6. 当前数据规模

- 节点共 132 个，节点编号无重复，经纬度无缺失。
- 按双模节点同时计入两类统计：短波能力节点 76 个，超短波能力节点 104 个。
- 任务场景 6 个，任务通联关系 432 条。
- 候选部署点 1100 个。
- 设备实例 414 个，设备型号 16 个，天线型号 78 个。
- 频率资源 94 条，干扰源 16 个。
- 网络拓扑链路 500 条，链路状态记录 2500 条。
- 故障案例 240 条，故障场景 5 个，故障规则 77 条，故障现象 15 条。
- DEM 网格 6504 x 5174，地物网格 7228 x 5750，道路约 7.6 万条。

说明：如果验收要求短波节点和超短波节点必须互相独立，则当前专用节点数量分别为 28 个和 56 个；该统计口径待项目组确认。

## 7. 已确认的部署环境

- 最终部署环境为甲方提供的国产化软硬件平台。
- 部署操作系统确定为国产麒麟操作系统。
- 软件应支持国产服务器、国产操作系统和国产数据库环境部署。
- 前端应避免依赖特定桌面操作系统能力，并满足国产化浏览器环境和离线部署要求。
- CPU 具体型号及架构尚未明确，可能为飞腾/鲲鹏等 ARM 架构，也可能为海光/兆芯等 x86 架构。
- 关系型数据库最终采用 MySQL 还是 openGaussDB 尚未明确。

CPU 架构和数据库选型不影响当前前端 Mock 开发，但会影响后续算法服务、图数据库和整体部署验证。

## 8. 已知限制和待确认事项

- `04_联调数据/` 中的大部分业务数据为合成数据。
- 真实的 16 个设备型号和 77 个天线型号尚未完成字段对齐并入；现有型号数据用于联调。
- 故障知识图谱目录暂时没有三元组数据。
- DEM 和地物数据的原始出处、授权状态待确认。
- 道路数据来自 OpenStreetMap，使用时应保留 ODbL 1.0 署名。
- 设备状态上报协议及接口文档待确认。
- Python 算法服务与 Java 后端之间的正式接口规范待确认。
- 接口鉴权方式、文件下载方式、分页规则待确认。
- ML 层故障诊断是否纳入本次验收范围待确认。
- 覆盖图层最终采用 GeoJSON、PNG，还是二者同时提供，待前后端确认。

## 9. 前端需优先反馈的事项

- 是否支持 GeoJSON 矢量图层和 PNG 地理叠加层。
- 地图组件使用的坐标顺序是否固定为 `[lon, lat]`。
- 异步任务采用轮询还是回调；当前资料按轮询设计。
- 大列表是否需要分页，以及默认页大小。
- 文件下载采用二进制响应、文件地址还是签名地址。
- 鉴权信息放置方式，例如 `Authorization` 请求头。
- 故障诊断结果、规则依据和影响范围在界面中的展示位置。

## 10. 使用顺序

1. 先阅读本文件及 `01_接口与算法文档/01_数据字典.md`。
2. 根据 `03_接口文档.md` 建立接口类型和统一响应处理。
3. 使用 `02_接口样例/` 开发 Mock 接口。
4. 使用 `04_联调数据/` 开发表格、图层和筛选功能。
5. 使用 `05_地理与原始数据/raw/` 开发 DEM、地物和道路图层。
6. 对第 8、9 节事项形成书面确认后，再冻结正式接口。
