# 短波/超短波智能规划系统

本仓库用于保存《短波/超短波智能规划系统》课题组侧资料、算法模块计划、需求草稿和相关文档。

## 项目目标

系统整体目标是建设一套面向短波/超短波通信网络的综合管控平台，覆盖设备孪生建模、智能网络规划、知识图谱、综合态势和故障诊断。

根据当前双方分工，课题组只负责 Python 算法模块；合作方负责 Java 全栈工程化实现。课题组本期工作以算法服务、算法模型、接口文档、测试数据和联调支持为主。

## 验收指标

系统级指标：

- 短波节点数量不少于 50 个。
- 超短波节点数量不少于 100 个。
- 地图最大范围不小于 120 km x 120 km。
- 态势刷新周期不超过 1 min。
- 规划预选配置不少于 3 种。
- 地形地貌场景不少于 2 种。
- 故障诊断场景不少于 4 类，最低非密要求不少于 3 类。
- 快速规划目标不超过 5 min，资料中另有不超过 4 min 表述，最终验收口径待确认。
- 精确规划目标不超过 20 min。
- 20% 节点失效后的增量重规划目标不超过 2 min。

课题组侧重点：

- 算法服务能处理不少于 150 个节点的样例数据。
- 智能规划接口能返回不少于 3 个候选方案。
- 干扰分析接口能返回 C/I 载干比、受影响链路和抗干扰建议。
- 链路质量评分接口能输出可供合作方态势界面使用的评分结果。
- 故障诊断接口能返回根因候选、影响范围、修复建议和置信度。

## 接口方式

双方通过以下方式联调：

- HTTP REST。
- JSON 请求/响应。
- 必要时由合作方通过 WebSocket 将算法结果推送到前端。

课题组算法服务建议统一放在 `algorithm-service/`，由合作方 Java 后端调用，不直接承担前端展示。

## 工程目录建议

```text
algorithm-service/    Python 算法服务，统一提供 REST 接口
algorithms/           规划、传播、干扰、评分、诊断算法实现
models/               NER、关系抽取、ML 故障诊断模型代码
data/                 脱敏样例数据、算法测试数据、标注样例
tests/                单元测试、接口测试、性能测试
docs/api/             与合作方联调的接口文档
docs/                 项目资料、需求草稿、输出文档和图件
```

当前资料目录：

- `docs/input/`：原始输入资料与需求模板。
- `docs/draft/`：需求章节 Markdown 草稿。
- `docs/output/`：需求规格说明书输出稿与阶段版本。
- `docs/reference/`：演示材料、技术路线说明等参考资料。
- `docs/assets/`：Visio 图件、压缩包等文档配套资产。
- `skills/`：写作辅助规则。
- `AGENTS.md`：文档写作范围、编号、边界与风险控制规则。
