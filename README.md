# 短波/超短波智能规划系统

本仓库用于实现《短波/超短波智能规划系统》软件项目，并保存项目资料、需求草稿、输出文档和配套图件。

## 项目目标

实现一套面向短波/超短波通信网络的综合管控平台，支持设备统一管理、GIS 态势呈现、网络智能规划、知识图谱查询和故障智能诊断。

核心模块：

- 设备孪生建模
- 知识图谱构建与查询
- 智能网络规划
- 综合态势呈现
- 故障智能诊断

## 验收指标

- 短波节点数量不少于 50 个。
- 超短波节点数量不少于 100 个。
- 地图最大范围不小于 120 km x 120 km。
- 态势刷新周期不超过 1 min。
- 规划预选配置不少于 3 种。
- 地形地貌场景不少于 2 种。
- 故障诊断场景不少于 4 类，最低非密要求不少于 3 类。
- 快速规划目标不超过 5 min，资料中另有不超过 4 min 表述，最终验收口径待确认。
- 精确规划目标不超过 20 min。
- 20% 节点失效后的增量重规划目标不超过 2 min。

## 推荐架构

建议采用前后端分离、算法服务独立、外部设备接入可替换的架构。

- 前端：React、TypeScript、Vite、OpenLayers、ECharts、D3.js。
- 后端主服务：Java 17、Spring Boot 3。
- 算法服务：Python 3.11、FastAPI。
- 关系数据库：openGauss 优先，开发期可兼容 PostgreSQL/MySQL。
- 图数据库：Neo4j。
- 缓存：Redis。
- 消息队列：RabbitMQ。
- 时序数据：InfluxDB 或 TimescaleDB。
- 实时推送：WebSocket。
- 部署：Docker Compose 开发版，后续适配国产化服务器、国产操作系统和国产数据库。

## 工程目录建议

后续实现代码建议按以下结构组织：

```text
frontend/             前端 GIS 态势和业务界面
backend/              Java 后端主服务
algorithm-service/    Python 规划、覆盖、干扰、诊断算法服务
device-simulator/     设备状态模拟器
deploy/               Docker Compose、部署脚本和环境配置
docs/                 项目资料、需求草稿、输出文档和图件
```

当前资料目录：

- `docs/input/`：原始输入资料与需求模板。
- `docs/draft/`：需求章节 Markdown 草稿。
- `docs/output/`：需求规格说明书输出稿与阶段版本。
- `docs/reference/`：演示材料、技术路线说明等参考资料。
- `docs/assets/`：Visio 图件、压缩包等文档配套资产。
- `skills/`：写作辅助规则。
- `AGENTS.md`：文档写作范围、编号、边界与风险控制规则。

## 实施计划

### 第 1 阶段：项目初始化，1 周

目标：搭好可持续开发的工程底座。

任务：

- 创建新的 Git 仓库。
- 建立 `frontend/`、`backend/`、`algorithm-service/`、`device-simulator/`、`deploy/` 目录。
- 搭建 React 前端、Spring Boot 后端、FastAPI 算法服务。
- 建立数据库初始模型：设备、站点、链路、任务、规划方案、告警、故障案例。
- 搭建 WebSocket 通道。
- 搭建本地一键启动脚本。

交付：

- 系统空壳可运行。
- 前端能打开地图。
- 后端能返回模拟设备数据。
- WebSocket 能推送模拟状态。

### 第 2 阶段：设备孪生建模，2 到 3 周

目标：完成设备数据底座。

任务：

- 实现设备、站点、链路基础管理。
- 支持固定站、车载站、短波设备、超短波设备。
- 建立设备四层模型：物理模型、参数模型、状态模型、地理模型。
- 实现设备模拟器，每 30 秒生成不少于 150 台设备状态。
- 实现设备状态采集接口。
- 实现虚拟设备面板：开关机、频率设置、功率设置、天线参数设置。
- 实现批量配置任务、进度推送和结果统计。

验收：

- 支持 50 个短波节点和 100 个超短波节点。
- 设备状态更新周期不超过 30 秒。
- 前端能展示在线、离线、告警状态。

### 第 3 阶段：GIS 综合态势，2 到 3 周

目标：形成“一张图看全网”的主界面。

任务：

- 接入离线地图或本地瓦片底图。
- 支持不小于 120 km x 120 km 的地图范围。
- 实现底图、设备、链路、覆盖热力、干扰源、告警图层。
- 实现站点、链路、干扰源标绘。
- 实现链路质量评分和颜色/粗细可视化。
- 实现 WebSocket 增量刷新。
- 实现告警高亮、定位和基础历史态势回放。

验收：

- 150 个节点同时显示。
- 态势刷新周期不超过 1 分钟。
- 告警能在地图上定位。

### 第 4 阶段：智能网络规划，4 到 6 周

目标：实现核心规划业务。

任务：

- 实现规划任务管理和通联关系配置。
- 支持 Excel/CSV 导入站点和任务通联关系。
- 实现 DSatur 频率分配初始解。
- 实现遗传算法或 NSGA-II 多目标优化。
- 输出不少于 3 种候选规划方案。
- 实现网络连通性分析。
- 实现超短波覆盖计算基础版，DEM 到位后接入 ITM/Longley-Rice。
- 实现短波链路计算基础版，后续增强 P.533。
- 实现干扰源标绘、影响分析和抗干扰建议。
- 实现方案比较和规划结果上图展示。

验收：

- 支持 150 节点规划。
- 输出不少于 3 种预选方案。
- 快速模式目标不超过 5 分钟。
- 支持 20% 节点失效后的增量重规划。

### 第 5 阶段：知识图谱，3 到 4 周

目标：实现静态图谱、人工维护、查询推理和可视化。

任务：

- 建立设备知识图谱、网络态势知识图谱、故障知识图谱。
- 实现图谱节点和关系维护。
- 实现 Neo4j 数据导入脚本。
- 实现 3 到 5 跳路径查询。
- 实现 D3 图谱可视化、节点展开和路径高亮。
- 预留 NER 自动抽取接口。

验收：

- 能维护三类图谱。
- 能从故障现象查询可能原因和解决方案。
- 能从设备查询关联模块、天线和链路。

### 第 6 阶段：故障智能诊断，3 到 4 周

目标：实现规则引擎加知识图谱推理的半年可交付版。

任务：

- 实现手动故障注入：低功率、高误码率、设备过温、链路中断、同频干扰。
- 实现阈值规则、持续时间判断、告警合并和优先级排序。
- 将告警指标映射为图谱故障现象。
- 查询候选根因、置信度和修复建议。
- 实现影响范围分析：受影响设备、链路、任务。
- 实现故障诊断报告。
- 实现人工确认后的故障案例回流。

验收：

- 支持不少于 4 类典型故障场景。
- 告警到初步诊断目标不超过 45 秒。
- 能生成诊断报告。
- 能在地图上显示故障位置和影响范围。

### 第 7 阶段：系统集成，2 周

目标：把五个模块串成完整工作流。

主流程：

1. 导入或标绘站点。
2. 创建设备和链路。
3. 模拟器持续上报设备状态。
4. 地图显示综合态势。
5. 创建规划任务。
6. 算法服务生成方案。
7. 方案上图展示。
8. 注入故障或触发告警。
9. 系统诊断根因。
10. 生成报告。

任务：

- 实现用户登录、角色权限和操作审计。
- 实现方案版本管理。
- 实现数据导入导出。
- 实现系统配置管理。
- 完成模块间接口联调。
- 统一 OpenAPI 接口文档。

### 第 8 阶段：性能优化与验收，2 到 3 周

目标：围绕验收指标压测、修补和打包。

测试项：

- 150 节点地图渲染。
- 150 节点状态刷新。
- 150 节点规划任务。
- 120 km x 120 km 地图范围。
- WebSocket 断线重连。
- 10 用户并发在线。
- 30 秒设备模拟上报。
- 快速规划、精确规划、增量重规划耗时。
- 故障诊断 45 秒响应。
- 图谱 3 到 5 跳查询。
- 国产化环境部署。

交付：

- 测试用例和测试报告。
- 部署手册和用户手册。
- 接口说明。
- 演示数据集。
- 可执行部署包。

## 关键风险与待确认事项

- 真实设备状态上报协议格式待确认。
- DEM 地形数据来源、范围和格式待确认。
- 国产化服务器 CPU 架构待确认。
- 是否必须接入真实光纤网络数据待确认。
- 知识图谱训练语料能否提供脱密版本待确认。
- Python 与 Java 的接口规范待确认。
- ML 层故障诊断是否纳入本期验收待确认。

## 实施策略

第一版不要等待所有外部条件确认。先使用设备模拟器、静态样例数据、基础规则诊断、人工维护图谱和简化传播模型把系统跑通；真实设备协议、DEM 数据、P.533、NER 自动抽取和 ML 诊断作为可替换增强项逐步接入。
