# 短波/超短波智能规划系统

本仓库用于保存《短波/超短波智能规划系统》课题组侧资料、算法模块计划、需求草稿和相关文档。

## 项目目标

系统整体目标是建设一套面向短波/超短波通信网络的综合管控平台，覆盖设备孪生建模、智能网络规划、知识图谱、综合态势和故障诊断。

根据当前双方分工，课题组只负责 Python 算法模块；合作方负责 Java 全栈工程化实现。课题组本期工作以算法服务、算法模型、接口文档、测试数据和联调支持为主。

## 验收指标

系统级指标：

- 短波节点数量不少于 50 个。
- 超短波节点数量不少于 100 个。
- 地图最大范围不小于 120 km x 120 km。
- 态势刷新周期不超过 1 min。
- 规划预选配置不少于 3 种。
- 地形地貌场景不少于 2 种。
- 故障诊断场景不少于 4 类，最低非密要求不少于 3 类。
- 快速规划目标不超过 5 min，资料中另有不超过 4 min 表述，最终验收口径待确认。
- 精确规划目标不超过 20 min。
- 20% 节点失效后的增量重规划目标不超过 2 min。

课题组侧重点：

- 算法服务能处理不少于 150 个节点的样例数据。
- 智能规划接口能返回不少于 3 个候选方案。
- 干扰分析接口能返回 C/I 载干比、受影响链路和抗干扰建议。
- 链路质量评分接口能输出可供合作方态势界面使用的评分结果。
- 故障诊断接口能返回根因候选、影响范围、修复建议和置信度。

## 接口方式

双方通过以下方式联调：

- HTTP REST。
- JSON 请求/响应。
- 必要时由合作方通过 WebSocket 将算法结果推送到前端。

课题组算法服务建议统一放在 `algorithm-service/`，由合作方 Java 后端调用，不直接承担前端展示。

## 6 周项目开发计划

根据《项目安排(1).pdf》，项目按 6 周推进，目标是打通两个完整流程：

- 无线网络规划流程：输入任务需求和通信资源，自动生成电台部署、通信路由、频率功率配置及优化方案，并由 GIS 界面展示规划结果。
- 故障诊断流程：输入故障场景和设备状态，完成故障定位、原因分析和影响评估，输出修复建议，并由 GIS 及故障诊断界面展示结果。

课题组不承担 Java 后端、前端界面、设备孪生工程、Neo4j 运维、GIS 图层渲染、WebSocket 推送和光纤网络工程实现。

课题组本期必须交付：

1. 可独立启动的 Python 算法服务。
2. 智能网络规划接口，能返回不少于 3 个候选方案。
3. 频率分配算法，包含 DSatur 初始解和 GA/NSGA-II 优化。
4. 覆盖计算接口，至少完成可运行基础版，ITM/P.533 按数据到位程度增强。
5. 干扰分析接口，输出 C/I、受影响链路和抗干扰建议。
6. 链路质量五维评分接口。
7. 故障诊断算法接口，输出根因候选、影响范围、修复建议和置信度。
8. 知识图谱模型侧能力，至少提供 NER/关系抽取训练代码、样例数据和推理接口骨架。
9. 与合作方联调用 OpenAPI 文档、样例 JSON、测试脚本和演示数据。

## 周计划

### 第 1 周：确定数据和接口

目标：根据现有软需明确 SR-4 无线网络规划、SR-5 故障诊断所需的数据类型、输入输出数据结构和前后端接口边界，形成可用于开发和测试的基础数据集。

主要任务：

- 明确设备、站点、任务通联、链路、覆盖范围、规划方案、故障结果等统一数据格式。
- 自行寻找并整理设备、站点、任务通联、地形、频率、故障等基础测试数据。
- 与前端开发人员明确算法模块向前端提供的数据，以及前端传入任务条件的数据格式。
- 完成数据字典、接口文档、基础测试数据集和模块接口关系说明。

第一周数据清单：

- `data/raw/dem/`：地形高程数据，建议 GeoTIFF，覆盖不小于 120 km x 120 km 区域。
- `data/raw/landcover/`：地物/土地覆盖数据，建议 GeoTIFF、GeoJSON 或 Shapefile。
- `data/raw/roads/`：道路数据，建议 GeoJSON 或 Shapefile。
- `data/raw/equipment_docs/`：短波/超短波电台公开参数、设备说明书。
- `data/raw/maintenance_docs/`：设备维修资料、故障处理资料。
- `data/synthetic/nodes/`：网络节点/站点数据，短波不少于 50 个节点，超短波不少于 100 个节点。
- `data/synthetic/tasks/`：任务通联关系，建议 5 到 10 组任务场景，每组 30 到 100 条通联关系。
- `data/synthetic/frequency/`：可用频段、频点、信道、占用状态和复用限制。
- `data/synthetic/interference/`：干扰源数据，建议 10 到 20 个干扰场景。
- `data/synthetic/topology/`：网络拓扑数据，建议 1 套 150 节点以上网络，200 到 500 条链路。
- `data/synthetic/link_status/`：网络运行/链路状态数据，建议 1000 条以上状态记录。
- `data/fault/cases/`：故障案例数据，建议 4 类故障，每类 50 到 100 条。
- `data/fault/knowledge_graph/`：故障知识图谱三元组，第一版建议 500 到 2000 条关系。
- `data/fault/rules/`：故障规则数据，第一版建议 50 到 100 条规则。
- `data/schemas/`：CSV/JSON 字段模板。
- `data/dictionary/`：数据字典、字段说明、枚举值和待确认事项。

### 第 2 周：完成电台部署规划

目标：完成无线网络规划中的电台部署部分，并向 GIS 前端提供可展示的部署结果。

主要任务：

- 根据任务区域、已有固定站、地形环境和任务通联需求，筛选候选部署位置。
- 计算移动电台数量和推荐部署坐标。
- 结合电台参数和传播条件，分析节点之间是否具备通信条件。
- 向前端提供部署点、候选点、覆盖结果接口，完成首次地图展示验证。

交付：

- 候选部署位置。
- 推荐电台数量。
- 推荐部署坐标。
- 基础通信关系。
- 覆盖结果。
- 部署规划模块和 GIS 部署结果展示。

### 第 3 周：完成路由和通信资源规划

目标：在电台部署位置确定后，完成通信路径、频率资源和电台参数配置，形成较完整的网络资源配置方案。

主要任务：

- 根据网络拓扑规划通信路径。
- 生成主用和备用通信路由。
- 为通信链路分配频率资源。
- 配置发射功率等电台参数。
- 检查不同链路之间的频率冲突或配置冲突。
- 对接路由拓扑、频率、功率、链路指标等接口，使前端能够展示完整规划方案。

交付：

- 路由与资源配置模块。
- 前端规划方案展示。

### 第 4 周：完成 SR-4 无线网络规划整体功能

目标：整合部署、路由、频率、功率配置和优化能力，形成可独立演示的 SR-4 完整版本。

主要任务：

- 完成网络整体方案优化。
- 生成和比较多套规划方案。
- 完成干扰源影响分析。
- 识别受干扰节点和链路。
- 生成抗干扰调整方案。
- 与 GIS 前端完成 SR-4 整体联调，实现方案生成、结果查看、多方案比较及地图展示。

交付：

- SR-4 完整功能演示版本。
- 接口联调记录。

### 第 5 周：完成故障定位和影响分析

目标：完成 SR-5 故障诊断核心功能中的故障知识、故障规则、故障定位、根因分析和故障影响计算。

主要任务：

- 整理常见故障类型、故障现象、设备状态、故障原因、历史故障案例和处理方式。
- 根据故障现象和设备状态判断故障设备、可能故障部件和故障原因。
- 识别受影响设备、受影响链路和影响等级。
- 对接故障场景输入、故障节点、受影响节点/链路、影响等级等展示接口。

交付：

- 故障诊断核心模块。
- 故障影响可视化联调。

### 第 6 周：完成故障建议和系统整体联调

目标：完成故障修复建议和诊断报告输出，整合 SR-5，并对整体系统进行功能与数据一致性测试。

主要任务：

- 根据故障定位和影响分析结果生成维修或处置建议。
- 输出故障对象、故障类型、故障原因、影响范围、处理建议和诊断报告。
- 完成 SR-5 与前端接口联调。
- 完成 SR-1/SR-2 前端、SR-3 资源数据、SR-4 规划、SR-5 诊断、SR-6 知识支撑之间的整体联调。
- 逐项检查对应 SR 需求是否已经实现。

交付：

- 完整系统设计。
- 完整演示版本。
- 软需符合性检查表。
- 接口文档。
- 测试报告。
