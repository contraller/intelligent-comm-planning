# 短波/超短波智能规划系统

本仓库用于实现《短波/超短波智能规划系统》软件项目，并保存项目资料、需求草稿、输出文档和配套图件。

## 项目目标

实现一套面向短波/超短波通信网络的综合管控平台，支持设备统一管理、GIS 态势呈现、网络智能规划、知识图谱查询和故障智能诊断。

核心模块：

- 设备孪生建模
- 知识图谱构建与查询
- 智能网络规划
- 综合态势呈现
- 故障智能诊断

## 验收指标

- 短波节点数量不少于 50 个。
- 超短波节点数量不少于 100 个。
- 地图最大范围不小于 120 km x 120 km。
- 态势刷新周期不超过 1 min。
- 规划预选配置不少于 3 种。
- 地形地貌场景不少于 2 种。
- 故障诊断场景不少于 4 类，最低非密要求不少于 3 类。
- 快速规划目标不超过 5 min，资料中另有不超过 4 min 表述，最终验收口径待确认。
- 精确规划目标不超过 20 min。
- 20% 节点失效后的增量重规划目标不超过 2 min。

## 推荐架构

建议采用前后端分离、算法服务独立、外部设备接入可替换的架构。

- 前端：React、TypeScript、Vite、OpenLayers、ECharts、D3.js。
- 后端主服务：Java 17、Spring Boot 3。
- 算法服务：Python 3.11、FastAPI。
- 关系数据库：openGauss 优先，开发期可兼容 PostgreSQL/MySQL。
- 图数据库：Neo4j。
- 缓存：Redis。
- 消息队列：RabbitMQ。
- 时序数据：InfluxDB 或 TimescaleDB。
- 实时推送：WebSocket。
- 部署：Docker Compose 开发版，后续适配国产化服务器、国产操作系统和国产数据库。

## 工程目录建议

后续实现代码建议按以下结构组织：

```text
frontend/             前端 GIS 态势和业务界面
backend/              Java 后端主服务
algorithm-service/    Python 规划、覆盖、干扰、诊断算法服务
device-simulator/     设备状态模拟器
deploy/               Docker Compose、部署脚本和环境配置
docs/                 项目资料、需求草稿、输出文档和图件
```

当前资料目录：

- `docs/input/`：原始输入资料与需求模板。
- `docs/draft/`：需求章节 Markdown 草稿。
- `docs/output/`：需求规格说明书输出稿与阶段版本。
- `docs/reference/`：演示材料、技术路线说明等参考资料。
- `docs/assets/`：Visio 图件、压缩包等文档配套资产。
- `skills/`：写作辅助规则。
- `AGENTS.md`：文档写作范围、编号、边界与风险控制规则。

## 一个月冲刺计划

目标是在 10.1 前完成可运行、可演示、可验收的压缩版系统。三人团队优先保证主流程闭环，不在本期深做真实设备协议、NER 自动抽取、ML 故障诊断、完整 P.533/ITM 工程化和国产化实机调优。

本期必须跑通的主流程：

1. 启动系统。
2. 地图加载不小于 120 km x 120 km 的区域。
3. 显示 50 个短波节点和 100 个超短波节点。
4. 设备模拟器持续上报状态。
5. 地图显示设备、链路、告警和干扰源。
6. 创建网络规划任务。
7. 算法服务生成不少于 3 个候选方案。
8. 规划方案上图展示和对比。
9. 注入典型故障。
10. 系统给出根因候选、影响范围、修复建议和诊断报告。
11. 查看故障知识图谱路径。

## 实施策略

第一版不要等待所有外部条件确认。先使用设备模拟器、静态样例数据、基础规则诊断、人工维护图谱和简化传播模型把系统跑通；真实设备协议、DEM 数据、P.533、NER 自动抽取和 ML 诊断作为可替换增强项逐步接入。
