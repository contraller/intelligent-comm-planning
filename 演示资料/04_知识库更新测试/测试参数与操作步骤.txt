名称：手工复测原因-20261029-01
类型 / 图谱：故障运维知识 · 原因（Cause）
描述：人工构造的原因节点，用于验证知识录入、保存和发布检索流程，不代表已确认的设备故障。
关键词（逗号分隔，最多 10 项）：手工复测,原因节点,20261029

其他：不新增属性、关系或步骤；适用设备型号留空；实体及变更单编号由系统处理，不手填。

操作：知识图谱 → 新增知识变更 → 填摘要 → 新增实体并照填 → 保存草稿 → 等待回执和详情读取结束
预期：草稿可重读且字段一致；当前已发布检索不包含此新名称。记录实际变更单及修订，不手填编号。

二、送审审核发布检索  SUP-KG-002
编辑者打开同一单 → 提交审核 → 确认送审 → 关闭 → 退出账号。
独立审核账号登录 → 知识维护 → 打开同一待审单 → 核对内容和来源 → 填审核意见 → 审核通过。
审核意见可填：已核对本单原因节点的名称、描述、关键词和构造数据来源，仅用于录入流程复测。
发布前检索新名称应无该新节点；具备发布权限的账号 → 发布已审核内容 → 确认发布。
检索已发布知识输入完整名称 → 检索 → 核对详情、实际发布版本、审核与发布记录。
作者不能审核自己的变更；审核通过与发布是两个动作；版本号按实际回执记录。

三、关闭与失败分支

SUP-KG-003 空摘要保存拒绝且长表单错误可见
1. 新增并填好实体，摘要保持空白，滚动到底部后点击“保存草稿”。
2. 查看固定底部失败提示及顶部错误；点击“查看问题”核对定位，然后尝试“提交审核”。
3. 点击“关闭”，在未保存提示中选择“继续编辑”，核对实体输入仍保留。
预期：保存失败，错误可见且可定位；真实 HTTP 应记录 422 / code=1001，已有实跑消息为“变更说明需为 1 至 500 字”；不得把 Mock 的 1–120 字校验提示当作 HTTP 返回。；失败后保留输入，不出现已保存成功提示，不产生成功保存回执或送审；点击提交审核若先保存失败，不继续送审。；取消离开保留输入；未保存保护仍生效。

SUP-KG-004 仅加入已有实体且只填摘要不能形成实际知识变更
1. 新建变更、填写摘要、加入已有实体，不改名称、描述、关键词、来源、属性或步骤。
2. 点击“保存草稿”，查看错误，再尝试“提交审核”。
3. 点击“关闭”后选择“继续编辑”，核对原字段仍保留。
预期：仅摘要或选择行不构成知识变更；真实 HTTP 拒绝保存，已有证据为 422 / code=1001“没有可保存的知识变更”。；不产生成功变更单、成功回执、修订递增或送审记录，不显示保存成功；原发布内容保持不变。；未保存输入保留；Mock 提示“没有相对已发布基线的实际修改”属于另一实现的测试证据，不能据此修改 HTTP 预期。

SUP-KG-005 保存或送审成功后直接关闭并退出
1. 保存有效草稿，等到“当前内容已保存，可直接关闭。”后点击底部“关闭”，重开同一单。
2. 点击“提交审核”并“确认送审”，等到“已提交审核，内容已保存，可直接关闭或退出账号。”后点击抽屉右上 X。
3. 切换到其他页面并退出账号，再由 E 登录重开原单核对状态和字段。
预期：成功保存后未再修改时，底部关闭、抽屉 X、路由离开和退出账号不重复弹出未保存确认。；关闭或退出不额外触发保存/送审，不产生重复业务回执；原单内容和待审核状态可重读。；若显示“保存已受理，但详情尚未核实”，应单独登记受理待核实，按提示重新读取，不重复提交，也不把它记为详情核实成功。

SUP-KG-006 保存忙态下 X、Esc 和底部关闭同步受限
1. 点击“保存草稿”，观察“正在处理，请稍候…”及待完成请求。
2. 处理未结束时依次尝试抽屉右上 X、Esc 和底部“关闭”，记录按钮状态与抽屉是否保留。
3. 等待成功并完成详情读取，再用 X 或底部“关闭”退出，恢复执行前的网络条件。
预期：知识变更抽屉在 locked 期间 X、底部关闭不可用，Esc 不关闭抽屉；输入与处理上下文保留，不弹出可绕过忙态的离开流程。；处理结束解除忙态；成功后可直接关闭，不因之前点击生成重复保存请求。

SUP-KG-007 抽屉 X 发起离开，确认框 X 取消，明确放弃才退出
1. 点击知识变更抽屉右上 X，确认出现“未保存的知识草稿”。
2. 点击该确认对话框自己的右上 X，核对原抽屉及摘要保留。
3. 再次点击抽屉 X，选择“继续编辑”，核对仍保留输入。
4. 点击底部“关闭”，在确认框选择“放弃输入”，核对退出；重新新建检查旧输入不残留。
预期：抽屉 X 发起离开保护；确认框 X 等同取消离开，不等同放弃，也不等同保存。；确认框 X 和“继续编辑”均保留原输入，再次退出仍需确认。；只有明确“放弃输入”才丢弃本次未保存输入并退出，不二次弹窗、不触发知识写入；既有已保存单和版本仍保留。

处置方案：构造处置：由人员复核供电与模块检测记录，按维护规程处理并记录复核结果。

记录构造的部件检测结论
复核处置记录并保留来源版本
现象来源：从所选诊断的冻结输入继承；反馈抽屉没有新增观察现象字段，不在根因文本中替代现象。
提交知识草稿 → 查看知识维护 → 核对案例与现象、根因、部件、方案、有序步骤及原诊断来源 → 按第二节独立审核发布。
单个原因节点不是完整案例，不会自动训练模型或改变旧诊断。没有冻结观察现象时不能用根因文字补造现象，记录前置条件不足。
