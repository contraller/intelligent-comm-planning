新增知识变更｜首次使用照填示例
更新日期：2026-10-29

在哪里使用
知识图谱 → 顶部“新增知识变更” → 在右侧抽屉逐项填写。
这是手工录入示例，不是导入文件。“新增知识变更”目前没有文件上传入口；不要把本文件或同目录JSON放进任务、资源或故障导入窗口。
本例不依赖规划结果、故障场景或诊断运行，可在首次登录后独立演示。
登录使用本包分配的业务编辑者；审核使用与作者不同、具审核权限的账号。账号及密码以本机账号文件为准，本文不提供固定密码。

先选一种演示
A：只想试一下“新增、保存”，按下一节填一条原因实体。
B：想展示一个有关联的知识图谱，直接按第二、三节填4个实体、3条关系（推荐）。
A、B是两份独立示例，不要在同一变更单混填；重复操作时把名称和摘要末尾“01”统一换为“02”等新批次。

一、简例A：一条原因知识
1. 点击“新增知识变更”，变更摘要填写：首次使用例程：新增原因知识-01
2. 点击“新增实体”，照填以下字段：
名称：例程-原因节点-01
类型 / 图谱：故障运维知识 · 原因
描述：用于演示原因知识的新增、保存与审核发布；该条目为人工编写的示例。
关键词（逗号分隔，最多10项）：首次使用,知识维护,原因
来源说明：首次使用演示例程，人工编写，用于知识维护流程演示。
3. 不添加说明属性、不新增关系，不填写实体编号，编号由系统分配。
4. 点击“保存草稿”，等待“当前内容已保存，可直接关闭。”；记录本次变更单编号。
5. 如需继续发布，按第四节执行；发布后检索“例程-原因节点-01”。
说明：原因实体没有适用设备型号选择是正常的；该字段只对设备知识显示。单独一条原因不是完整故障案例，也不会自动训练模型。

二、完整例B：先填摘要，再新增4个实体
变更摘要：首次使用例程：新增功放异常知识链-01

实体编号不手填；未保存时显示“保存时分配实体编号”，属于正常状态。

以上四个实体的可选说明属性、单位等均不用添加；本例不填写设备型号，不录入设备控制指令。
每张卡片都需要填写自己的“来源说明”；只填摘要或只选择原有条目，不构成实际知识变更。

三、在同一变更单中新增3条关系
填完4个实体后，再点击“新增关系”三次。
在“头实体”和“尾实体”下拉框中按名称选择同一批次的“本单新增”实体，不要手填JSON中的key或其他环境的E-编号。

关系类型：处置方式
尾实体：例程-核对供电与连接-01

权重为空表示本例未声明量化关联权重；不要为凑数填写置信度。需要自行填写时，界面允许0～1。
展开“变更前后预览”，应有4项新增实体、3项新增关系；以当前实际预览内容为准。

四、保存 → 送审 → 不同账号审核 → 发布
1. 编辑者点击“保存草稿”，等待保存与详情读取完成。看到“当前内容已保存，可直接关闭。”后，记录系统生成的变更单编号和修订。
2. 如校验失败，查看固定底部提示或“查看问题”，按中文字段定位补全。不要重复点击保存；提交未完成时，关闭按钮和右上角X会暂时禁用。
3. 点击“提交审核” → “确认送审”，等待“已提交审核，内容已保存，可直接关闭或退出账号。”，确认状态“待审核”。
4. 关闭抽屉，退出作者账号；用不同的审核账号登录。首次登录先完成该账号的初始密码修改。
5. 知识图谱 → “知识维护” → 找刚才记录的变更单 → “查看 / 处理”。核对摘要、作者、4个实体、3条关系及来源。
6. 审核意见可填：已核对本单实体、关系及来源，仅用于知识维护流程演示。
7. 点击“审核通过”。注意：审核通过后还没有发布。
8. 具发布权限的账号点击“发布已审核内容” → 核对本单 → “确认发布”，等待状态“已发布”，记录本次新知识版本。
作者不能审核自己的变更；没有独立审核账号或权限不足时，停在当前实际状态，不跳过审核。若基线过期，按页面提示重新核对，不改写旧版本号。

五、检索新内容并展示关系
1. 知识图谱 → “图谱浏览”，勾选“故障运维知识”，实体类型选择“故障”。
2. 在“检索已发布知识”输入“例程-功放输出异常-01”，点击“检索”。
3. 选中本次新实体，点击“展开选中实体一跳”。
4. 应能查看本次录入的现象、原因、处置方案及三条关系；选节点看详情，点关系看来源。
5. 进入“版本记录”，核对本次发布快照与审核来源。不得预设KGV-2或旧变更单编号，以本机实际回执为准。
发布前在已发布知识中检索不到新名称属于正常情况。发布后若看不到，先核对变更单状态、筛选条件和本次发布版本，不另造一套同名数据。

六、演示时可以这样讲
“我们先创建知识变更，新增一条故障及其现象、候选原因、处置建议，再把它们关联起来。保存只生成草稿；另一位审核人核对后，还需要单独发布。发布后，使用者才能在图谱中检索到新内容并浏览关联。这里演示的是知识维护与版本流程，不会自动改变旧诊断结论、训练模型或向设备下发命令。”
