首次使用例程
通信规划与故障诊断

从导入输入开始：实际计算并确认方案，完成三例诊断与影响分析，再走知识反馈、独立审核和发布。

先说明范围：全部数据为人工构造、非现场实测；候选根因与建议需人工复核。ML未启用，没有真实设备下发。首次运行按步骤生成本机结果，是否达标以本次作业为准。

打开可照读讲稿 阅读手册 PDF 打开手册 Word 知识库更新测试步骤

本页可离线阅读。请在实际系统网页中操作；CSV是输入文件，解压和导入不等于已经完成计算。

1．启动、登录并改密

运行包内启动入口，等待自动打开系统网页。没有自动打开时，按 app/data/runtime/访问地址.txt 中的实际地址访问，端口以该文件及自动打开的网页为准。

首次登录先在本机查看 app/data/runtime/首次登录账号.txt，使用分配账号登录并修改初始密码。后面的审核账号也须完成首次登录改密；不要把账号文件或密码放进报告、截图或知识内容。

2．两份任务文件一起选 → 预检 → 应用 → 保存

打开规划导入文件夹

系统中打开网络规划 → 第1步“任务与约束输入” → 导入。在文件选择框内按住 Ctrl，同时选中以下两份CSV，一次打开，不能分两次上传。

  • 01_task_scenarios.csv：任务条件。
  • 02_task_links.csv：通联需求。

确认页面列出两个文件 → 解析并校验 → 查看预览、差异及问题列表 → 无问题后确认替换当前草稿（应用） → 回到表单核对 → 保存任务，等待保存回执。

任务应为 DEMO-FIRST-PLAN，名称“首次使用例程 通信规划与故障诊断”；3个参与节点、1条需求 DEMO-FIRST-D01。通联为 ND-0001 → ND-0002，64 kbps、100 ms、最低可靠性0.95、MAX_RELIABILITY、备份true、balanced预设。

其余参数保留官方输入：必要通联true、P1、数据量10 MB、数据业务、station端点模式、available-hf。短波与超短波排除频点均为空，沿用包内原频池，无需扩频。预检报错先停下核对；不要换预设或修改条件来绕过问题。若提示已有同编号任务，先确认是否继续前次输入。

3．提交规划 → 等进度 → 核验原门槛

保存成功后点一次提交规划，观察“2 · 规划计算与结果”的进度，等待本次作业完成。记录本次作业编号；查询中断用页面重试入口，避免重复提交。

展开查看约束依据，查看路由、频率及完整配置，按本次实际结果核对：

检查项继续条件
必要通联100%
抗毁性≥90%
中继≤2跳
频率冲突0处

对应检查全部通过且配置完整，才进入下一步。必要通联与全体通联分开读取；业务可靠性0.95与网络抗毁性分别检查。覆盖率若显示“未计算”，不能称覆盖达标。

未通过就保留本次编号、实际指标与缺口，停止本例后续确认链路并交维护人员核对。最新版允许完整未达标方案经显式风险确认转正；本例只走全部通过分支，风险转正不等于达标。此前构造参考抗毁性91.01%仅供了解，不能照抄为本次结果。首次运行按步骤生成本机结果，是否达标以本次作业为准。

4．保存，再确认本次方案

全部通过后：下一步：保存或调整方案 → 保存方案 → 填写含“首次使用例程”和本次时间的名称、注明人工构造与待复核 → 保存为方案。

记录本次方案编号，再点转正并设为当前方案 → 核对弹窗 → 确认转正，核对“已转正 · 当前方案”。保存与确认是两次操作，均以本次回执为准。

到GIS的“查看已保存方案”，按本次编号打开冻结网络。任务态势只展示输入，不能代替冻结结果。确认方案没有向真实设备下发。

5．故障导入：先选新确认网络，再核对对象

打开故障导入文件夹

进入故障诊断，必要时点“重新加载”。点导入场景，在“绑定当前有效方案”中明确选择第4步本次新确认方案，再选择 05_故障场景_三类示例.csv。

选文件后自动读取、预检，无需另找“解析/预检”按钮。先核对这三例：

  • 短波功放：DEVICE DV-0214；驻波比告警、功率接近零。
  • 超短波链路中断：LINK OL-0001；对端失联、握手超时。
  • 超短波配置不一致：DEVICE DV-0279；频率配置与对端不一致。

对象编号按配套示例提供，导入前须在本次冻结网络中核对。必须核对新网络中的对象类别、设备归属与链路两端；编号存在本身不足以证明适用。无问题后点整批导入，记录本次场景编号；导入尚未启动诊断。

对象缺失、类型或端点不符、预检报错时先停止，交维护人员按新网络调整CSV后重新预检。不要盲绑其他对象或旧网络。

6．三例分别诊断 → 等影响分析 → 看报告

逐个选择新导入场景，核对本次网络，点一次开始诊断。保持页面打开和执行权限；当前前端会在诊断就绪后自动衔接提交影响分析，不用另找提交按钮，也不是点“影响”标签才开始计算。

每例都查看依据 → 根因 → 影响 → 建议，等诊断与影响两个阶段均就绪，再点预览与下载完整报告。查询失败用“重试查询”；只有根因而影响未完成时不能称两阶段完成。

核对报告属于本次方案、场景和运行，记录三例各自新编号。根因、置信度及影响按本次返回讲解，保留证据缺项和人工复核提示，不把候选原因讲成已测实或已修复。

7．知识反馈草稿 → 送审 → 不同账号审核 → 发布

  1. 建议选择第三例本次运行，点知识反馈。按实际结果填写故障类型、根因、部件、处置建议及诊断步骤，注明“人工构造、非实测、待现场复核、未执行下发或维修”。
  2. 点提交知识草稿，等待“知识草稿已保存”，记录本次新案例号和变更单编号。草稿尚未发布。
  3. 到知识图谱 → 知识维护，打开本次变更单，核对来源、实体关系和基线；修改后先保存，再提交审核 → 确认送审。
  4. 退出作者账号，使用不同于作者、具审核权限的账号登录，首次登录先改密。核对本单内容与构造边界，填写审核意见，符合范围后审核通过。
  5. 再由有发布权限的账号点发布已审核内容 → 核对本单 → 确认发布，确认“已发布”。审核通过与发布是两个动作。

无独立审核账号或权限不足，就停在实际状态；基线过期按页面提示核对和重新送审，内容有误则驳回修订。知识发布不表示现场验证完成，也没有训练ML模型。

8．搜索本次新案例号

先在版本记录 → 本次新版本“快照与差异” → 审核来源核对本次变更单及独立审核记录。

再到图谱浏览，勾“故障运维知识”，类型选“故障”，在“检索已发布知识”输入第7步返回的本次新案例号 → 检索 → 选本次实体 → 展开选中实体一跳。

核对本次任务输入、作业、确认方案、三例场景与运行、反馈变更单和发布版本能逐项对应。未完成就记录未完成，检索不到就保留实际结果排查。讲稿末尾提供本次记录栏。

操作到哪一步，就按本次证据说明到哪一步。此例只展示构造数据流程；非现场实测、需人工复核、ML未启用、无真实设备下发。

此页和配套CSV为2026-10-28准备版本；按钮以安装版本实际页面为准。文件夹按钮用于显示导入资料，真正导入须在系统内完成。
