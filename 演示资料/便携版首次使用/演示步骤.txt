Windows便携包首次使用演示步骤（可照读）
日期：2026-10-28
适用：从全新便携包导入输入并实际完成本轮操作。
状态：首次运行按步骤生成本机结果，是否达标以本次作业为准。

开场可照读
“今天从输入开始，依次做通信规划、故障诊断和影响分析，再把本次分析整理为知识草稿，经独立审核后发布。这里使用人工构造的数据，不是现场实测。候选根因与处置建议需要人工复核；ML未启用，没有真实设备下发。”

先看文件位置
包根目录：首次使用演示.html（离线操作指引）。
包内规划输入：首次使用演示/01_规划任务导入/01_task_scenarios.csv
              首次使用演示/01_规划任务导入/02_task_links.csv
包内故障输入：首次使用演示/02_故障场景导入/05_故障场景_三类示例.csv
包内讲稿：首次使用演示/演示步骤.txt
包内手册：用户手册/用户手册.docx、用户手册/用户手册.pdf
CSV是输入，不是已计算结果。手册、讲稿和报告不上传到导入窗口。首次使用需要实际提交计算，不能把解压、导入或保存任务说成已经计算完成。

1｜启动、首次登录与改密
操作：运行包内启动入口，等待自动打开系统网页；未自动打开时，按app/data/runtime/访问地址.txt中的实际地址访问。端口以该文件及自动打开的网页为准。
首次登录：在本机阅读app/data/runtime/首次登录账号.txt，使用分配的账号登录，并按页面提示修改初始密码。审核账号也按相同要求首次登录并改密。不要把账号文件或密码发入报告、截图或知识内容。
核对：页面可登录，初始密码已修改；后续作者与审核人使用不同的授权账号。
可照读：“我们先按本包生成的地址进入系统，用首次登录账号完成登录和改密。后面由另一个有审核权限的账号审核知识。”

2｜一次选中两份任务CSV，先预检
当前页面：网络规划 → 第1步“任务与约束输入” → “导入”。
操作：打开首次使用演示/01_规划任务导入/，按住Ctrl同时选中01_task_scenarios.csv和02_task_links.csv，再点“打开”。确认页面列出两份文件，点“解析并校验”，检查预览、差异和问题列表。
应看到：
任务编号 DEMO-FIRST-PLAN；名称“首次使用例程 通信规划与故障诊断”。
3个参与节点：ND-0001、ND-0002、ND-0003；1条需求：DEMO-FIRST-D01。
通联方向ND-0001 → ND-0002；P1、必要通联true、数据量10 MB、速率64 kbps、最大时延100 ms、最低可靠性0.95、数据业务、station端点模式。
路由策略MAX_RELIABILITY（最高可靠性），请求备份路由true；参数预设balanced（均衡）。
频率方案available-hf；短波与超短波排除频点均为空，其余频率条件与官方输入保持一致，沿用包内原频池，无需扩频。
核对：两个CSV是一套，不能分两次逐个上传。出现未知节点、字段错误、频率问题或引用错误时，先停止并保留提示，交维护人员核对。若提示已有同编号任务，先确认是否继续此前首次使用任务，不能把覆盖输入称为新任务。
可照读：“一份文件说明任务，一份说明谁与谁通信。预检只核对输入和资源引用，此时没有开始规划。”

3｜应用到草稿，再保存任务
操作：预检无问题后，点“确认替换当前草稿”（应用到草稿）；回到任务表单，按第2步核对参数，再点“保存任务”，等待“任务已保存”。展开“任务详情与版本”，记录本次输入版本与资源版本。
核对：不要换预设、载入另一整套任务或修改原指标来消除问题；不额外添加频点。保存结果不确定时使用“核实保存结果”，不要连续重复保存。
可照读：“应用把输入放进表单，保存才形成任务输入版本。我们保留原参数和包内频池，下面再提交计算。”

4｜提交规划，等待本次进度
操作：保存成功后，点一次“提交规划”。在“2 · 规划计算与结果”查看进度和阶段，记录本次作业编号，等待终态及本次结果。查询中断时用页面“恢复查询”或实际显示的重试入口。
核对：不能用旧结果代替本次结果，也不能因等待而重复提交；失败时保留原编号、错误信息及实际进度。耗时以本机执行为准。
可照读：“现在才开始计算。我们等待本次作业完成，提交规划不会自动创建故障场景或启动诊断。”

5｜核验原门槛，只走全部通过分支
操作：展开“查看约束依据”，查看“路由路径”“频率分配”和“查看完整配置”，逐项核对本次结果。
继续条件：必要通联100%；抗毁性≥90%；中继≤2跳；频率冲突0处；对应检查全部通过且配置完整。
必要通联连通率与全体通联连通率分别读取，不能相互代替。单条业务最低可靠性0.95与网络抗毁性分别检查。覆盖率如显示“未计算”，照实记录，不能宣布覆盖达标。
此前构造参考的抗毁性为91.01%，仅为此前结果参考。首次运行按步骤生成本机结果，是否达标以本次作业为准；不保证得到相同数值，不作为本次成功证据。
任一检查未通过、配置不完整或结果仍为参考状态：保留本次结果与缺口，停止本例后续确认链路，交维护人员核对；不降门槛、不扩频、不改库、不反复换输入求成功。
最新版支持完整未达标方案经显式风险确认转正；该分支不等于指标达标，本次首次例程不使用该分支。
可照读：“先核对真实结果。只有原门槛全部通过且配置完整，我们才继续保存并确认。若有缺口，就如实停在这里，不把风险接受讲成达标。”

6｜保存方案，再确认本次方案
操作：检查全部通过后，点“下一步：保存或调整方案” → “保存方案”；填写名称“首次使用例程 通信规划与故障诊断”并附本次时间，保存说明写“人工构造、非实测、需人工复核、无真实下发”；点“保存为方案”。
记录本次方案编号，再点“转正并设为当前方案” → 核对弹窗名称 → “确认转正”。核对“已转正 · 当前方案”。
核对：保存与确认是两次操作，均须有本次回执。GIS中通过“查看已保存方案”找到该编号，“打开冻结网络”核对；“查看任务态势”只看任务输入，不能代替冻结方案。
可照读：“保存固定本次结果，确认把它设为本任务当前采用的方案。接下来的故障场景必须引用这一份新确认网络。确认配置没有向真实电台下发。”

7｜故障导入先选新确认网络，再核对三例对象
当前页面：故障诊断；必要时先点“重新加载”更新来源目录。
操作：点“导入场景”，在“绑定当前有效方案”中明确选择第6步本次新确认方案；核对任务、方案编号及冻结网络，再选择首次使用演示/02_故障场景导入/05_故障场景_三类示例.csv。
选中文件即自动读取、预检，没有单独的“解析/预检”按钮。查看三例的名称、对象类别、编号、归属及链路两端；确认无问题后点“整批导入”。
三例输入：
① 首次使用例程 短波设备功放故障：DEVICE DV-0214，HW_FAILURE；SY-0001、SY-0002，构造现象为驻波比告警、功率读数接近零。
② 首次使用例程 超短波链路中断：LINK OL-0001，LINK_DOWN；SY-0005、SY-0007，构造现象为对端完全失联、握手超时。
③ 首次使用例程 超短波频率配置不一致：DEVICE DV-0279，SW_CONFIG；SY-0012，构造现象为频率配置与对端不一致。
对象编号按官方三类示例提供，首次运行须在本次冻结网络中核对。即使编号存在，也要核对其短波/超短波类别、设备归属及链路端点。
若对象不存在、类别或端点不符、预检报错，停止该批导入，交维护人员按新冻结网络核对并调整CSV后重新预检；不得盲绑其他对象或其他网络。
核对：导入只保存场景，不启动诊断。记录本次生成的三个场景编号，不复用旧场景或旧运行编号。
可照读：“故障要落在本次网络中的具体设备或链路上。这些是构造现象，先核对对象，正确导入后才逐例诊断。”

8｜三例分别诊断，等待前端衔接影响分析
操作：依次选择每个新导入场景，核对绑定的是本次新确认方案，点一次“开始诊断”；若页面提示未保存，先保存并核对场景。保持页面打开和执行权限，观察进度。
当前前端在诊断就绪后，会自动衔接提交第二阶段影响分析；无需另找“提交影响分析”按钮，点击“影响”标签也不是启动操作。
先查看“依据”“根因”，再等待影响阶段就绪；三例均须分别检查“影响”“建议”、最终状态及报告是否可用。记录每例本次运行编号。
查询失败用“重试查询”，不要反复点“开始诊断”。只有候选根因而影响尚未完成时，不能宣布两阶段完成。失败或缺项按实际记录，不填入旧结论。
可照读：“诊断先整理候选原因，页面接着提交影响分析。我们等两个阶段都完成，再分别看三例结果。根因、置信度及影响按本次返回讲解，候选原因仍需人工复核。”

9｜核对并导出本次报告
操作：每例依次查看“依据”“根因”“影响”“建议” → “预览与下载完整报告”；按需下载本次DOCX、PDF或JSON。
核对：报告中的任务、方案、场景与运行编号对应本轮记录；保留规则部分匹配、证据缺项和人工研判提示。报告可读不等于故障已修复。
可照读：“报告记录输入、依据、候选原因和影响，便于复核与留档。构造诊断不代替现场检测或维修确认。”

10｜从本次运行提交知识反馈草稿
操作：建议选择第三例本次运行，点“知识反馈” → 在“诊断知识反馈”中核对诊断结论，填写“人工确认故障类型”“根因”“故障部件”“处置方案”“诊断步骤” → “提交知识草稿” → 等待“知识草稿已保存” → “查看知识维护”。
填写原则：按本次真实返回整理，注明“人工构造、非实测、候选待现场复核、未执行下发或维修”。根因写本次候选与待复核说明，处置写建议，步骤记录观察现象、依据与证据缺项，不预填旧答案。“人工确认故障类型”字段不表示候选根因已获现场证实。
记录系统本次返回的新案例号、实体编号和变更单编号；草稿尚未发布，不是已发布知识，也未训练ML。
可照读：“我们把本次分析整理为带来源的知识草稿，保留构造与待复核说明，再交由另一个账号审核。”

11｜作者送审，不同审核账号审核，再单独发布
作者操作：知识图谱 → “知识维护” → 找本次变更单 → “查看 / 处理” → 核对摘要、实体关系、来源和基线；如有修改先“保存草稿” → “提交审核” → “确认送审”，确认状态为“待审核”。
审核操作：退出作者账号；使用与作者不同且有审核权限的授权账号登录，首次登录先改密。进入本次变更单，核对来源、构造说明、证据、实体关系与作者，填写审核意见；符合演示范围后点“审核通过”。
发布操作：审核通过后，再由有发布权限的账号点“发布已审核内容” → 核对本次变更单和基线 → “确认发布”，核对“已发布”。
核对：作者与审核人不得是同一账号。无独立审核账号或权限不足时，停在页面实际状态，不能称已发布；内容不符合时驳回修订；基线过期按页面提示重新核对和送审，不跳过流程。
可照读：“保存草稿、送审、独立审核和发布是四个动作。只有确认发布后才进入可检索版本，发布仍不代表候选故障已被现场证实。”

12｜搜索本次新案例号，检查本轮记录
操作：知识图谱 → “版本记录” → 本次新版本“快照与差异” → “审核来源”，核对本次变更单与独立审核记录；回“图谱浏览” → 勾选“故障运维知识” → 类型选“故障” → 在“检索已发布知识”输入第10步本次新案例号 → “检索” → 选择本次实体 → “展开选中实体一跳”。
核对：检索对象属于本次新发布内容；任务输入版本、作业、确认方案、三例场景与运行、反馈变更单和发布版本能够对应。检索不到就保留实际结果排查，不用其他案例替代。
可照读：“现在用本次新案例号查发布结果。每一步都引用这次生成的记录，便于回看来源。这里完成的是构造数据流程，ML未启用，没有真实设备下发，候选根因与处置建议仍需人工复核。”

独立入口补充｜不跑规划，直接演示“新增知识变更”
知识图谱 → 新增知识变更。打开同目录“03_知识变更示例/知识变更填写示例.txt”，可选一条原因简例，或照填4个实体、3条关系的完整例。
该抽屉是手工录入，没有上传文件按钮；配套JSON只供字段对照，不是可导入格式。文件中已列摘要、名称、类型、描述、关键词、来源、头尾实体和关系类型。
按示例保存草稿 → 送审 → 不同账号审核 → 单独发布 → 检索新名称并展开一跳。此流程可独立于前面的规划、故障诊断执行，编号以本机回执为准。
