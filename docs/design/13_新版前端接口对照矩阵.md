## 状态与数据边界

| 标记 | 含义 |
|---|---|
| 复用待接 | 后端已有相应契约，新版前端尚未接入或尚未通过真实 HTTP 页面验收 |
| 算法待适配 | 算法接口可执行，但缺页面所需的版本、回执、列表、字段或持久化契约 |
| 新增待做 | 当前没有可复用的完整后端业务接口 |
| 外部待确认 | 真实身份、设备上报、观测或第三方协议未确定；只能提供明确标注的联调演示数据 |

现有 `GET /api/v1/auth/session` 仅用于显式联调模式：默认规划员，加可切换的独立编辑者和审核者，不等于正式登录。现有 `data/synthetic/` 是构造资料；新增联调会话、故障运行和回执由 SQLAlchemy 持久化，响应及页面保留“构造联调数据，非生产/非实测”。持久化不代表设备在线、真实频谱观测或真实故障诊断已完成。SR5 使用既有页面 `SAMPLE`，身份目录使用 `SYNTHETIC_INTEGRATION`。

资源底座增量（0014）：通过显式初始化将现有构造资料保存为不可变数据库快照，新版交付入口固定使用数据库模式；同版目录/分页/详情/预设和版本化 SR4 使用同一输入。首次初始化沿用原资源业务版本，不使现有任务失效；未初始化/迁移失败/内容损坏直接报错，不降级读取文件。0015 接入单设备参数并由本批复用回执表完成上下架，不新增表；不因此将第 6～8 项整类功能标记完成。

参数批后端 246/前端相关 287 项通过；上下架本批后端全量 270/前端相关 314 项通过、构建通过。真实页面单台/批量下架启用、取消、筛选、无变化回执与重启重放通过；下架状态 SR4 原始结果明确排除两个设备，141 节点/165 链路，恢复后新方案为 141 节点/166 链路。DV-0001 挂高仍 17.1 m，414 台均在架，当前 resource-f82ea3157ad8d95b；历史资源/方案保留，不把恢复当作旧方案重新有效。完整证据及既有前端宿主测试失败见进度台账。

MVT 道路是前端静态资源：`/maps/demo-roads-tiles/manifest.json` 与版本化 `.mvt` 瓦片由静态服务提供，不新建算法或业务 API。其来源和许可见新版前端 `public/maps/ATTRIBUTION.md`。本批真实浏览器已验证 GIS 道路默认关闭、开启后只显示 DEM 重叠区域，不修改原坐标或许可。

新版网络规划、诊断及 GIS 地图复用同一 DEM 校验加载器：严格核对源哈希、范围、CRS 及实际 PNG 哈希，地形置于业务层下方；错版/失败保留点线。诊断网络需由后端核验方案冻结指纹，历史缺失时不能套用当前地形。规划/诊断道路默认关闭，GIS 保留开关，不改道路数据。后台视口去重、尺寸通知合帧及滚动隔离已回归；真实浏览器在 1280×720 四页各 10 次空闲采样的位置/滚动一致且无新增 API，1440×1000 GIS 也通过。此为具体窗口和已测交互的验收，不代替全部操作/平台验收。

唯一静态同源入口为 `scripts/serve_delivery.py`，当前 `http://127.0.0.1:5183` 沿用原 SQLite。已验证任务整行和按钮打开、编辑/审核身份切换、图谱列表与实体子图；1100/390 宽度图谱导航可见。SR5/SR6 所有写操作的浏览器全闭环仍须与既有真实 HTTP 闭环区分。

## 实施顺序与验收门槛

1. **已有能力迁移**：先将新版任务、SR4 规划、只读资源与 SR5/SR6 现有后端路径逐项接入；复用前先核对请求、响应和错误码，不把旧版测试等同新版页面验收。
2. **持久化资源底座**：再做构造联调资料的版本化编辑、导入/导出、上下架与 GIS 同快照投影；资源变更应使规划结果失效或要求重算。
3. **业务工作流**：补频谱、干扰、设备状态/配置、观测帧、SR5/SR6 新版 DTO 与缺失操作。无真实外部协议的流程只返回持久化构造记录及明确来源。
4. **系统管理与安全**：演示账户、角色、参数和审计可先作隔离联调实现；正式认证及设备控制须另行确认，不以演示回执冒充交付完成。

每一批在修改前单独列出文件白名单、字段与错误码、迁移及测试范围，经确认后实施。通过标准至少包括：服务端输入拒绝分支、幂等/版本冲突、数据库重启回读、前端严格解码测试、真实 HTTP 按钮操作和来源标签可见；测试桩与真实联调分别登记在 `12_后端接口实施进度.md`。
