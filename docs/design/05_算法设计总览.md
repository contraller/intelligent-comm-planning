# 算法设计总览 v0.1

> 本文档用于指导第 2 周以后算法开发，不作为软件需求规格说明书正式章节正文。
> 数据字段以 `docs/design/01_数据字典.md` 和 `data/README.md` 为准。

## 1. 设计目标

算法侧第一版目标是用现有 `data/` 数据跑通无线网络规划和故障诊断两条主流程，形成可供 Java 后端和 GIS 前端联调的稳定输入输出。

当前算法输入数据已经具备：

- 节点、设备、天线、任务通联、频率资源、干扰源、拓扑链路、链路状态。
- 候选部署点、主备路由样例、频率冲突约束、故障案例、故障规则。
- DEM、地物、道路、设备资料和维修资料的本地原始数据归档。

## 2. 数据流

```text
任务场景 + 节点设备 + 频率资源
        |
        v
候选部署点筛选
        |
        v
移动电台数量与位置规划
        |
        v
拓扑链路构建 / 链路预算
        |
        v
主备路由规划
        |
        v
频率分配与冲突检查
        |
        v
覆盖计算 / 干扰分析 / 方案评分
        |
        v
规划方案输出给 GIS 前端
```

故障诊断流程：

```text
故障场景 + 设备状态 + 链路状态 + 故障规则
        |
        v
规则诊断
        |
        v
图谱推理（第一版可用规则派生三元组占位）
        |
        v
ML 诊断（第一版可降级）
        |
        v
三路融合 / 两路降级融合
        |
        v
影响节点与链路分析
        |
        v
修复建议和诊断报告
```

## 3. 模块划分

### 3.1 候选部署点筛选

输入：

- `data/synthetic/nodes/nodes_v1.csv`
- `data/synthetic/nodes/candidate_sites_v1.csv`
- DEM、地物、道路原始数据

核心判断：

- 坡度不超过阈值。
- 地物类型允许部署。
- 距道路距离不超过阈值。
- 与既有节点保持最小间距。
- 对指定节点满足通视或传播可达条件。

输出：

- 候选点列表。
- 筛除原因统计。
- 推荐等级和评分。

### 3.2 电台部署规划

输入：

- 候选部署点。
- 固定站、移动站、任务通联关系。
- 设备型号和天线约束。

第一版算法建议：

- 贪心覆盖：每轮选择能满足最多未覆盖必要通联关系的候选点。
- 多方案生成：改变评分权重，生成不少于 3 个候选方案。
- 约束不可满足时返回盲区和放宽建议。

输出：

- 推荐部署点。
- 推荐移动电台数量。
- 被覆盖通联关系。
- 未覆盖通联关系和建议。

### 3.3 路由规划

输入：

- `data/synthetic/topology/topology_links_v1.csv`
- `data/synthetic/tasks/task_links_v1.csv`
- `data/synthetic/topology/routes_v1.json`

第一版算法建议：

- 主路由：按链路代价最短路径计算。
- 备用路由：在主路由链路禁用后再次寻路。
- 链路代价综合距离、链路余量、链路状态和优先级。

输出：

- 主用路由。
- 备用路由。
- 跳数、总距离、瓶颈链路、估计可靠度。
- 不可达通联清单。

### 3.4 频率分配

输入：

- `data/synthetic/frequency/frequency_resources_v1.csv`
- `data/synthetic/topology/topology_links_v1.csv`
- `data/synthetic/topology/frequency_conflicts_v1.csv`

第一版算法建议：

- 将链路作为图节点，冲突约束作为图边。
- 使用 DSatur 生成初始可行解。
- 频率不足时返回缺口统计。
- 后续可接 GA 或 NSGA-II 优化频率复用、干扰风险和功率配置。

输出：

- 链路到频率资源的分配关系。
- 冲突清单。
- 频率缺口统计。
- 是否无冲突。

### 3.5 干扰分析

输入：

- `data/synthetic/interference/interference_sources_v1.csv`
- 拓扑链路、频率分配结果、设备参数。

第一版算法建议：

- 以频率重叠、距离衰减和发射功率估算 C/I。
- 输出受影响链路和影响等级。
- 给出换频、降功率、增设中继或调整路由建议。

输出：

- 受影响链路。
- C/I 和影响等级。
- 抗干扰建议。

### 3.6 故障规则诊断

输入：

- `data/fault/cases/fault_cases_v1.csv`
- `data/fault/rules/fault_rules_v1.csv`
- `data/dictionary/symptom_dict_v1.csv`
- `data/synthetic/link_status/link_status_v1.csv`

第一版算法建议：

- 根据 `symptom_ids` 和 `device_selftest` 匹配规则。
- 多条规则命中时按优先级和置信度排序。
- ML 路未启用时使用 `TWO_WAY_DEGRADED` 标识。

输出：

- 故障类型、故障部件、根因候选、置信度。
- 规则证据和来源案例。
- 修复建议。
