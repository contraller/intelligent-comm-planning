# 前端第一版需求验收清单

检查日期：2026-10-16  
适用技术栈：Vue 3 + TypeScript  
接口基础路径：`/api/v1`

## 1. 验收边界

前端第一版应覆盖完整业务导航、主要页面、表单、地图交互、结果展示和系统管理入口。
尚未接通的后端能力可以使用与接口文档一致的 Mock 数据，但不得省略页面、字段、加载状态、
空状态、失败状态和结果展示区域。

前端负责地图、页面、表单、图层、表格、状态反馈和业务流程编排。部署优化、传播计算、
路由规划、频率分配、干扰计算、故障推理和图谱推理由算法服务完成。前端不得直接访问算法
数据库，不得在页面内复制正式算法，也不得把 Mock 结果标记为真实计算结果。

第一版现场检查按以下三级记录：

| 结论 | 判定标准 |
|---|---|
| 通过 | 页面存在，核心操作可执行，状态完整，字段与接口文档一致 |
| 部分通过 | 页面已完成，但使用 Mock、接口尚未接通或存在非阻断性展示问题 |
| 不通过 | 页面缺失、关键操作不可执行、字段结构不一致或主流程无法继续 |

## 6. 无线网络规划

规划页面应采用步骤向导，顺序为：任务与区域 → 候选站址 → 台站部署 → 路由 → 频率 →
电台参数与覆盖 → 多目标优化 → 干扰分析 → 方案比较与确认。允许返回上一步修改，修改上游输入后
应将下游旧结果标记为失效，不能继续当作当前方案。

| FE-040 | 规划任务 | 新建任务，填写任务名称、规划区、任务站点、通联关系和约束；支持保存草稿 | SR-3.2-019 |

| FE-044 | 频率分配 | 显示网系或链路的分配频点、冲突、频点缺口、不可分配原因和调整入口 | SR-3.2-023 |

## 12. 明天现场必须演示的 8 条主流程

1. 登录 → 工作台 → 切换到设备管理、网络规划、态势监控、故障诊断和系统管理。
2. 在地图切换地形、地物、道路、站点和链路图层，点击节点和链路查看详情。
3. 新建一个站点或设备，修改、查询、地图定位，再执行停用或删除。
4. 新建规划任务，至少走通“候选站址 → 部署 → 路由 → 频率 → 参数/覆盖 → 方案确认”。
5. 在地图新增干扰源，修改参数，运行干扰分析，查看受扰链路、建议和路由重构结果。
6. 新建故障场景，执行诊断，查看分路依据、影响范围、修复建议并生成报告。
7. 新增一条故障知识，提交审核、审核发布，再用相同现象验证新知识可以被检索或推理命中。
8. 查看用户、角色、日志、导入导出记录和报告管理页面。

任一主流程不能继续时，现场记录阻断步骤、请求地址、请求体、响应体、控制台错误和负责人，不能只记录
“接口有问题”或“页面未完成”。

## 13. 第一版允许暂缺但必须留出接口的位置

- 真实设备开关机和状态上报：协议未提供，可 Mock，但页面与状态必须存在。
- 光纤网络真实数据：责任边界未确认，可预留类型、图层和“待接入”状态。
- 真实频谱采集：协议未提供，可用样例曲线或空状态，接口位置必须保留。
- 非结构化文档自动抽取和机器学习诊断：语料与验收边界未确认，不作为首版硬性项。
- 国产 CPU、国产数据库实机验证：环境未提供前不能完成，但前端不得引入明显不兼容依赖。
- 第二地形场景的真实数据：至少具备场景切换结构，正式数据和验收口径仍需确认。
