## 3. 问题的数学表述

### 3.1 符号

| 符号 | 含义 |
|---|---|
| $V_F$ | 已有固定站集合（22 个） |
| $V_T$ | 任务节点集合（134 个） |
| $V = V_F \cup V_T$ | 已有节点 |
| $S$ | 候选部署位置集合（当前 88 个可部署） |
| $X \subseteq S$ | 决策变量：实际部署移动电台的位置 |
| $D$ | 通联需求集合，$d_k = (s_k, t_k, m_k, r_k, \tau_k, \rho_k)$ |
| $m_k \in \{0,1\}$ | 该需求是否为**必要通联关系** |
| $G(X)$ | 在节点集 $V \cup X$ 上、按链路可行性判据建立的无向图 |
| $A$ | 规划区栅格化后的格点集合（覆盖率计算用） |

### 3.2 链路可行性判据

两点 $u, v$ 之间可建立有效链路，当且仅当

$$ M(u,v) \;=\; P_t + G_t + G_r - L(u,v) - N - \mathrm{SNR}_{req} \;\ge\; M_{\min} $$

其中 $L(u,v)$ 由 `propagation.py` 给出（超短波：自由空间 + 地形绕射 + 地物杂波；
短波：地波与 NVIS 天波取较小损耗），$N$ 为噪声底（短波按外部噪声 40 dB、
超短波按接收机噪声 8 dB），$\mathrm{SNR}_{req}$ 按业务类型取 8/10/15 dB，
$M_{\min}$ 为链路余量门限（默认 6 dB，可配置）。

**短波与超短波是两个独立的网络**（频段不同，不能互联），因此
$G(X)$ 实际是两个不相交的子图，两类网络分别规划。

### 3.3 需求满足判据

需求 $d_k$ 被满足，当且仅当 $s_k$ 与 $t_k$ 在 $G(X)$ 中连通，
且存在一条路径满足跳数上限 $H$（默认 $H=2$ 跳中继，对齐 SR-4.2.4 b）。

记 $\sigma_k(X) \in \{0,1\}$ 为需求 $k$ 的满足指示。

### 3.4 覆盖率判据

规划区按 $\Delta$（默认 1 km）栅格化得格点集 $A$，$|A| \approx 14400$。
格点 $a$ 被覆盖，当且仅当存在 $u \in V_F \cup X$ 使 $M(u,a) \ge M_{\min}$。
覆盖率 $C(X) = |\{a : \text{covered}\}| / |A|$。

### 3.5 两个子问题

**P1（最少电台数，对应 SR-4.2.1.2 b）**

$$
\min_{X \subseteq S} |X| \quad \text{s.t.} \quad \sigma_k(X) = 1 \;\; \forall k: m_k = 1, \qquad C(X) \ge \theta
$$

**P2（给定数量求最优位置，对应 SR-4.2.1.2 a/c）**

$$
\max_{X \subseteq S, |X| = p} \;\; f(X) = \alpha \sum_{k} w_k \sigma_k(X) \;+\; \beta\, C(X)
$$

其中 $w_k$ 按优先级加权（P1/P2/P3 = 5/3/1，必要通联关系额外加权）。

**两者均为 NP-难。** P1 含最小中继节点放置（Minimum Relay Node Placement，
可归约自节点权重 Steiner 森林）；P2 含最大覆盖选址问题（MCLP，可归约自集合覆盖）。
在无 ILP 求解器的条件下，本方案采用**构造性启发式 + 局部搜索**，
并**给出下界以量化解的质量**（见 4.5）。

## 4. 代码方案

### 4.1 模块划分

```
scripts/planning/
    __init__.py
    feasibility.py    链路可行性矩阵：调用 propagation，产出邻接结构
    viewshed.py       径向视域与覆盖位图
    deployment.py     P1 / P2 求解器
    metrics.py        方案评估指标与下界

algorithm-service/app/
    deployment.py     HTTP 接口层，对接 POST /plan/deployment
```

沿用现有约定：纯标准库、中文注释、随机过程固定种子。

### 4.2 第一步：预计算链路可行性矩阵

**这是整个方案能满足「≤5 分钟」的关键。** 传播计算昂贵（每条链路需沿剖面采样
48 个地形点），但搜索过程需要反复查询链路是否可用。做法是**一次性预计算，
之后的组合搜索只做位运算**。

需要计算的点对：

| 点对 | 数量（当前规模） |
|---|---|
| 候选点 × 已有节点 | 88 × 156 = 13 728 |
| 候选点 × 候选点 | 88 × 87 / 2 = 3 828 |
| 已有节点 × 已有节点 | 已在 `link.csv` 中，直接复用 |

合计约 1.76 万条，每条 48 次地形采样 ≈ 84 万次 `GridRaster.sample`，
实测单次采样约 1.5 μs，**预计 2–4 秒**。

产出：
- `feasible[i][j]` 布尔矩阵（用 Python `int` 位图存储，每行一个大整数）
- `margin[i][j]` 链路余量，用于后续排序与方案评估

> 选择位图（`int` 作 bitset）的理由：Python 大整数的 `|`、`&`、`bin(x).count('1')`
> 由 C 实现，比列表或 `set` 快一个数量级以上，且无需第三方包。
> 88 个候选 × 244 个点位，每行位图仅 244 bit。

### 4.3 第二步：覆盖位图（径向视域）

对每个候选点计算其覆盖的格点集合，存为位图 `cover[x]`（长度 $|A|$）。

直接对 14400 个格点逐点做传播计算代价过高（88 × 14400 = 127 万次链路预算，
每次含 48 次地形采样 ≈ 6000 万次采样，约 90 秒，虽在预算内但挤占余量）。
采用**径向视域算法（R3 变体）**：

```
对每个候选点 x：
    对方位角 θ = 0, Δθ, 2Δθ, ... (Δθ = 2°，共 180 条射线)：
        沿射线以 Δr = 250 m 向外步进至最大作用距离 R：
            维护该射线上已出现的最大仰角 maxang
            当前点仰角 ang = atan((h_ground + bulge - h_tx) / r)
            若 ang > maxang：该点通视，maxang = ang
            结合链路预算判定是否被覆盖，置位到 cover[x]
```

每个候选点 180 × 160 = 28 800 次采样，88 个候选点约 253 万次，**预计 4–6 秒**。
射线步进天然复用了剖面，避免了逐点重算整条剖面的 $O(n^2)$ 浪费。

> 这一步同时产出 SR-4.2.1 扩展流 1 要求的**盲区范围**：
> 全部候选点与固定站的覆盖位图取并集后，未置位的格点即为盲区。

### 4.4 第三步：P1 求解（最少电台数）

朴素的「每轮选新增满足需求最多的候选点」贪心在本问题上**会停滞**：
两个中继单独加入都不能连通任何一对需求端点，只有同时加入才行，
此时所有候选点的边际增益均为 0，贪心无法继续。

因此采用**辅助图上的节点权重 Steiner 森林**构造：

1. 在已有节点上建图 $G_0$，求连通分量 $\{C_1, C_2, \dots\}$；
2. 标出必要通联关系中两端不同分量的「待连接分量对」；
3. 构造辅助图 $H$：
   - 顶点 = 各连通分量（权重 0）∪ 候选点（权重 1）
   - 边 $(C_i, x)$：候选点 $x$ 与分量 $C_i$ 中任一节点链路可行
   - 边 $(x, x')$：两候选点之间链路可行
4. 对每对待连接分量，在 $H$ 上求**节点权重最短路**（Dijkstra，权重为路径上候选点数），
   路径长度即所需中继数；受跳数上限 $H$ 约束时限制路径上候选点数 ≤ $H$；
5. 按 KMB 思路，在「分量对 — 最短路代价」的度量闭包上做 Kruskal 式合并，
   **已被选中的候选点权重置 0**，使后续路径优先复用已部署的电台；
6. 若覆盖率仍低于 $\theta$，继续用**贪心补点**：每轮选 `cover[x]` 新增置位数最多的候选点
   （此时目标函数是纯覆盖，**是单调子模的**，贪心有 $1 - 1/e$ 近似保证）；
7. **冗余消除**：逐个尝试移除已选点，若移除后所有必要需求仍满足且覆盖率仍达标，则永久移除；
8. **1-交换局部搜索**：尝试用未选候选点替换已选点，若严格改善则接受，直到无改进或超时。

第 5–8 步全部是位运算与图遍历，**不再调用传播模型**，预计 2–5 秒。

### 4.5 解质量的下界

启发式必须能自证质量。本方案输出两个下界：

**下界 1（分量合并下界）**：设必要通联关系涉及的连通分量共 $q$ 个需并为若干组，
单个候选点最多能直接连接 $\delta_{\max}$ 个不同分量，则所需电台数
$\ge \lceil (q - g) / (\delta_{\max} - 1) \rceil$，$g$ 为目标分组数。

**下界 2（覆盖下界）**：设单个候选点覆盖格点数上限为 $c_{\max}$，
未被固定站覆盖的格点数为 $n_u$，则为达到覆盖率 $\theta$ 所需电台数
$\ge \lceil (\theta|A| - |\text{已覆盖}|) / c_{\max} \rceil$。

取两者较大值作为 $LB$，方案报告中给出 $\text{gap} = (|X| - LB)/LB$。

**小规模精确校验**：当 $|S| \le 18$ 且最优解 $\le 3$ 时，直接枚举
$\binom{18}{3} = 816$ 种组合求精确最优，用于回归测试中验证启发式的正确性。

### 4.6 第四步：P2 求解（指定数量）

$f(X)$ 中覆盖项子模、需求满足项不子模（连通性有阈值效应），因此：

1. **贪心构造**：每轮选 $\Delta f$ 最大的候选点，直至 $|X| = p$；
2. **Teitz-Bart 交换局部搜索**：对每个已选点与每个未选点尝试交换，
   接受首个改善解（first-improvement），循环至无改进或超时；
3. 记录搜索过程中遇到的所有非支配解，供多方案输出。

> **诚实说明**：$1 - 1/e$ 的近似保证**仅对覆盖项成立**，
> 整体目标含非子模项，无理论保证。质量以 4.5 的下界和小规模精确解来度量。

### 4.7 多方案生成（甲方指标：≥3 种）

| 方案 | 生成方式 | 侧重 |
|---|---|---|
| 方案 1 | P1 结果 | **最经济**：满足必要通联的最少电台数 $p_{\min}$ |
| 方案 2 | P2，$p = p_{\min} + 1$ | **覆盖优先**：多一部电台换覆盖率 |
| 方案 3 | P2，$p = p_{\min} + 2$，目标权重偏向需求满足 | **保障优先** |
| 方案 4+ | GRASP：贪心随机化（每轮从 Top-$k$ 中按权重随机选），不同种子 | 备选，输出非支配解 |

各方案统一给出对比指标：电台数量、必要需求满足率、全部需求满足率（按优先级加权）、
覆盖率、盲区面积、平均链路余量、最大跳数。

### 4.8 接口

对接 `docs/design/03_接口文档.md` 已定义的 `POST /plan/deployment`，异步任务模式：

```
POST /plan/deployment   →  202 {task_id, estimated_sec}
GET  /tasks/{id}        →  {status, progress, stage}
GET  /tasks/{id}/result →  {solutions: [...], blind_zones: [...]}
```

`progress` 按四个阶段推进：可行性矩阵 20% → 覆盖位图 50% → 求解 85% → 评估 100%。

无可行解时返回 `code=3001` 与 `suggestions`（对应 SR-4.2.1.2 扩展流 1），
建议内容由约束诊断给出：指出是候选点不足、链路余量门限过高，还是覆盖率目标过高。

### 4.9 计算时间预算（对照甲方「≤5 分钟」）

| 阶段 | 当前规模预计 | 说明 |
|---|---|---|
| 链路可行性矩阵 | 2–4 s | 1.76 万条链路 × 48 采样 |

## 6. 需要请教的问题（本方案最不确定的地方）

**这一节是最希望得到意见的部分。**

1. **无 ILP 求解器是否可接受？**
   项目约束为纯标准库（国产化部署），因此只能用启发式。当前规模（候选点 88、
   必要需求 69）其实不大，若允许引入求解器（如 CBC/HiGHS）或自写分支定界，
   P1 有可能求到精确最优。**是坚持纯标准库用启发式 + 下界，还是值得为精确性破例？**

2. **P1 的建模是否合适？**
   我把「最少电台数满足通联需求」建模为**节点权重 Steiner 森林**（候选点权重 1，
   连通分量为终端），用 KMB 式启发式求解。另一种常见建模是直接做**集合覆盖**
   （每个候选点覆盖一批需求）。我认为集合覆盖建模无法正确处理「两个中继串联才能连通」
   的情形，所以选了前者。**这个判断对吗？有没有更标准的做法？**

3. **「满足任务区域覆盖要求」该怎么量化？**
   需规原文只说「满足任务区域覆盖要求」，没有给数值定义。我拟定义为：
   规划区按 1 km 栅格化，格点到至少一个站点的链路余量 ≥ 6 dB 即为覆盖，
   覆盖率阈值 $\theta$ 默认 0.9、可配置。**这个定义是否合理？$\theta$ 与栅格粒度取多少合适？**

4. **通联需求满足与区域覆盖，两个目标怎么权衡？**
   SR-4.2.1.2 a 讲「覆盖最优」，b 讲「满足通联需求的最少电台数」，二者并非同一目标。
   我当前处理为：P1 以通联需求为硬约束、覆盖率为附加约束；P2 以加权和为目标。
   **实际工程上这两者的主次关系应该是怎样的？**

5. **跳数上限应在哪一步施加？**
   SR-4.2.4 要求中继跳数 ≤2。我在 P1 中已按 ≤2 约束路径。
   但 SR-4.2.1.2 本身没提跳数。**提前施加会不会过度约束、导致本可行的方案被判无解？**

6. **短波与超短波是否应分别规划？**
   两者频段不同不能互联，我拟分别求解再合并结果。
   但一个车载站可能同时装短波和超短波电台，此时两网的候选点选择是耦合的。
   **是否需要联合建模？还是分开规划、在方案评估时再考虑共址收益？**

7. **与 SR-4.2.4 多目标优化组网的边界在哪？**
   SR-4.2.4 要在部署与频率分配完成后，再以连通性、总辐射功率、抗毁性做多目标优化。
   本算法已经在优化连通性与覆盖。**两处是否会重复优化甚至互相打架？
   SR-4.2.1.2 是否应当只保证「可行」，把「最优」全部留给 SR-4.2.4？**

8. **传播模型尚为占位实现的影响。**
   链路可行性判据依赖传播模型。当前超短波用单刃形绕射，多障碍路径会偏乐观；
   短波 NVIS 用虚高 300 km 的简化几何，未考虑 foF2 时变。
   **在真实模型替换前先做部署算法，风险是否可接受？还是应当先完成传播模型？**
