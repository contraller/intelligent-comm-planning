## 这份数据是干什么用的

系统的故障诊断（SR-5.2）要求**三路并行推理再融合**：规则引擎、**知识图谱**、机器学习模型，
各出一个置信度，加权得到最终的故障类型判定。知识图谱是其中一路，
负责**根因溯源** —— 从观察到的现象出发，沿实体间的关系链找到根本原因和对应的处置方案。

举例：系统观察到「发射时驻波比告警」，图谱沿
`驻波比告警 --causedBy--> 馈线接头进水短路 --locatedAt--> 天线馈线 --resolvedBy--> 更换馈线并做防水`
这条链推出结论，同时把这条链作为**判定依据**返回给用户查看。

所以三元组不是随便记录知识，而是要**能串成链**。这决定了下面的命名一致性要求。

目前 `data/fault/knowledge_graph/` 是**空的**，这是第 5–6 周故障诊断的前置。

## 产出格式

文件：`data/fault/knowledge_graph/fault_triples_v1.csv`
模板：`data/schemas/fault_triples_template.csv`

```csv
triple_id,head,head_type,relation,tail,tail_type,weight,source_doc
KG-0001,功放模块输出级晶体管击穿,Cause,locatedAt,功率放大模块,Component,0.95,FM24-19.pdf
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `triple_id` | 是 | `KG-0001` 起顺序编号，四位补零 |
| `head` | 是 | 头实体名称，**中文** |
| `head_type` | 是 | 头实体类型，见下表，**只能用英文码值** |
| `relation` | 是 | 关系类型，见下表，**只能用英文码值** |
| `tail` | 是 | 尾实体名称，中文 |
| `tail_type` | 是 | 尾实体类型 |
| `weight` | 否 | 关系强度 0–1，见下方「权重怎么给」 |
| `source_doc` | **是** | 这条知识出自哪份资料，写文件名。SR-6.3 要求推理结果可溯源 |

## 实体类型与关系类型

### 本次要做的两个域

**故障域**（主要工作量，从 240 条故障案例来）

实体类型：`Fault` `FaultType` `Symptom` `Cause` `DiagnosisStep` `Solution` `Tool` `Spare`

**设备域**（次要，从设备手册来）

实体类型：`Device` `DeviceModel` `Component` `Interface` `Antenna` `Function` `Parameter` `Manufacturer`

> 态势域（`Node` `Link` `Metric` `LinkState` 等）本次**不做** ——
> 那部分由链路运行数据自动生成，不需要人工整理。

### 关系搭配表（**最重要的一张表**）

每种关系只能连接特定类型的实体。填表时先想清楚「头是什么类型、尾是什么类型」，
再挑关系。搭配错了，图谱推理会走不通。

**故障域**

| relation | head_type | tail_type | 含义 |
|---|---|---|---|
| `hasSymptom` | `FaultType` / `Fault` | `Symptom` | 该类故障表现为某现象 |
| `causedBy` | `Symptom` / `Fault` | `Cause` | 现象由某原因引起 |
| `locatedAt` | `Cause` / `Fault` | `Component` | 原因定位到某个部件 |
| `diagnosedBy` | `Symptom` / `Fault` | `DiagnosisStep` | 通过某步骤来诊断 |
| `resolvedBy` | `Cause` / `Fault` | `Solution` | 由某方案解决 |
| `affects` | `Fault` | `Device` / `Link` / `Node` | 故障波及的对象 |
| `propagatesTo` | `Fault` | `Fault` | 一个故障引发另一个故障 |
| `requiresTool` | `Solution` | `Tool` | 处置需要的工具 |
| `requiresSpare` | `Solution` | `Spare` | 处置需要的备件 |

**设备域**

| relation | head_type | tail_type | 含义 |
|---|---|---|---|
| `hasComponent` | `DeviceModel` | `Component` | 设备由哪些部件组成 |
| `hasInterface` | `DeviceModel` | `Interface` | 设备有哪些接口 |
| `hasAntenna` | `DeviceModel` | `Antenna` | 设备配套哪些天线 |
| `hasFunction` | `DeviceModel` | `Function` | 设备具备哪些功能 |
| `hasParameter` | `DeviceModel` | `Parameter` | 设备的参数项 |
| `producedBy` | `DeviceModel` | `Manufacturer` | 厂家 |
| `supportsMode` | `DeviceModel` | `Function` | 支持的工作模式 |
| `constrainedBy` | `DeviceModel` / `Function` | `Parameter` | 受某参数约束 |

## 怎么做：从一条故障案例展开

故障案例表已经把每条案例拆成了四段：**现象 → 原因 → 诊断步骤 → 处置方案**。
一条案例通常能展开出 5–9 条三元组。

拿真实案例 `FM24_002` 举例（原文为英文，需译成中文）：

```
fault_type       HW_FAILURE
symptom_text     No noise from speaker (AM-6879)
root_cause       Speaker off; squelch too high; amplifier/converter faulty
diagnosis_steps  Check speaker switch and squelch; evaluate amplifier/converter
solution         Turn speaker on; turn squelch counter-clockwise; HCM required
source_doc       FM24-19.pdf
```

注意 `root_cause` 里用分号列了**三个**并列原因，要拆成三条 `causedBy`。展开结果：

```csv

KG-0013,扬声器无声,Symptom,causedBy,扬声器开关未开启,Cause,0.8,FM24-19.pdf
KG-0014,扬声器无声,Symptom,causedBy,静噪电平设置过高,Cause,0.8,FM24-19.pdf
KG-0015,扬声器无声,Symptom,causedBy,放大器变换器故障,Cause,0.7,FM24-19.pdf
KG-0016,放大器变换器故障,Cause,locatedAt,放大器-变换器AM-6879,Component,0.95,FM24-19.pdf
KG-0017,扬声器无声,Symptom,diagnosedBy,检查扬声器开关与静噪电平,DiagnosisStep,0.9,FM24-19.pdf
KG-0018,扬声器开关未开启,Cause,resolvedBy,打开扬声器开关,Solution,1.0,FM24-19.pdf
```

## 四条质量要求

### 1. 实体命名必须前后一致（**最容易出错的地方**）

同一个东西在所有三元组里必须**用完全相同的字符串**。图谱是靠字符串匹配串联的，
`功放模块` 和 `功率放大模块` 会被当成两个不同的实体，链就断了。

做法：另建一张对照表随时查，写一个记一个。命名约定：

- 部件用全称：`功率放大模块`，不要写 `功放`
- 现象用「主语 + 状态」：`发射时驻波比告警`，不要写 `驻波比问题`
- 原因用「部件 + 失效方式」：`馈线接头进水短路`
- 方案用动宾结构：`更换功率放大模块`

### 2. 不要重复

同一组 `(head, relation, tail)` 只能出现一次。不同案例得出同样的知识时，
合并为一条，`source_doc` 用分号列多个来源。

### 3. 权重怎么给

| 情形 | weight |
|---|---|
| 资料里明确的因果或从属关系 | 0.9–1.0 |
| 资料列为「可能原因之一」（多个并列原因） | 0.6–0.8 |
| 依据经验推断、资料未明说 | 0.4–0.6 |

留空也可以，但同一批数据尽量统一风格。

### 4. 不要编造

资料里没有的关系不要凭想象加。`source_doc` 必填就是为了这个 ——
每条知识都要能回溯到具体哪份资料。整理不出足够条数，**宁可少也不要编**，
缺口我这边知道了可以另想办法补。
