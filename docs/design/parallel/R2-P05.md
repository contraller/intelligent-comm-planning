## 5. 可复用接口与共享接线签名

### 5.1 后端专用边界

- `create_system_management_router(*, authorize, service) -> APIRouter`：`authorize(request, permission, writing=False) -> SystemActor` 由主会话注入，默认不提供任何身份回退。
- `SystemActor`：服务端提供 `account_id/session_id/identity_revision/permissions/auth_source/authenticated_at`；`auth_source=LOCAL_PASSWORD`，账号必须仍启用。请求不得提交 actorId、permissions 或 roleName 来影响授权。
- `SystemManagementService(*,session_factory,permission_registry,request_key,clock=time.time)` 为实际构造签名；不连接隐式默认库，不以 frontend permission 字典作为服务端权威。request_key 为至少32 bytes的显式秘密配置。
- 实际审计签名 `append_system_audit(session,actor,*,now,action,object_id='',request_id=None,outcome='SUCCESS',error_code='',changes=None,snapshot=None,module=None) -> SystemAuditEvent`，在调用方事务内追加。module 为服务端模块名；actor 必须来自正式 require；snapshot 只可由服务端当前身份生成，绝不把 raw_body/密码/客户端成功声明交给 sink。资源等模块可在自己的业务事务中调用；跨不同数据库事务不能宣称原子，需要总集成明确。
- 实际本地适配 `LocalIdentityService.require(request,permission=None,*,writing=False) -> SystemActor` 和 `require_identity(...) -> 正式snake_case DTO dict`；后者兼容既有 `account_id/display_name/role_id/role_name/permissions` 消费者，不提供不存在的 resolve_local_session 公共方法。只在验证真实会话、账号、角色与期限后生成。

### 5.2 前端专用边界

- `createSystemManagementHttp(request: AuthenticatedRequest): Methods`；Methods 是现有 SystemServices 系统方法选集与 SystemManagementActions 的交集，路径相对于已有 `/api/v1` 客户端，不另建 Cookie 管理器。

## 6. 精确 HTTP 契约提案

所有路径以 `/api/v1` 为前缀，成功沿用 `{code:0,message,data}`。严格拒绝未知字段，不把未知事实补为正常、0 或成功。专用内部版本 `system-management-0.1`，身份继续沿用 `formal-identity-boundary-0.1`；对既有认证客户端的兼容由 R 请求解决。

公共分页：`pageNum>=1,pageSize=5/10/20/50,search` 最多 200 字；每页返回 `{items,total,pageNum,pageSize,revision}`。列表按服务端稳定键排序，空结果为真实空页。写入公共 `Mutation={baseRevision,requestId}`，非空 requestId 最多 120 字；`Result={revision,objectId,changed,operationId,reauthenticationRequired?}`。认证写入不要求配置 baseRevision，但仍有会话/CSRF 绑定。

| 归属 | 方法与路径 | 精确请求主体/查询 | 响应 data 与权限 |
|---|---|---|---|
| A/R | `GET /auth/capabilities` | 无 | `{authMode:LOCAL_PASSWORD,initialized,passwordChangeRequired,passwordPolicy:{minScalars:15,maxScalars:128},capabilities:{passwordMaintenance:true,anonymousRecovery:false}}`；匿名可读，不列账号/角色名单或密码提示 |
| A/R | `GET /auth/session` | Cookie，不收 actorId | 匿名 `null`；合法会话为首批正式身份 DTO；同源客户端适配后进入 AuthIdentity，不改变业务数据来源 |
| A/R | `GET /auth/csrf` | 当前 Cookie | `{csrf_token,session_id:null|string}`；匿名短期挑战有界，不能初始化业务账户 |
| A/R | `POST /auth/login` | `{username,password}`，匿名 CSRF、同源检查 | 新正式 DTO 与 HttpOnly 会话 Cookie；无账号/错误密码/停用账号的未认证响应统一，拒绝账号枚举 |
| A/R | `POST /auth/logout` | `{}`，绑定会话/CSRF | `null`；重复退出可确认已退出，不得退出另一标签刚替换的账号 |

### 6.1 错误语义

| HTTP / 业务码 | 本轮含义 |
|---|---|
| 422 / 1001 | 字段/类型/分页/权限编码格式或密码策略无效；响应只列字段和原因，不回传密码等输入 |
| 404 / 1002 | 允许访问范围内的账号、角色、参数、事件不存在 |
| 401 / 1101 | 凭据无效或受保护调用缺少认证；匿名 session GET 本身成功返回 null |
| 401 / 1102 | 会话过期、撤销或密码变更导致失效 |
| 403 / 1103 | 已认证主体停用；登录阶段不单独泄漏此事实 |
| 403 / 1104 | 无权限、越权角色授予或跨主体回执读取 |
| 403 / 1105 | CSRF 或同源校验拒绝 |
| 409 / 1106 | 会话关联/代次已变化，冻结旧表单，不自动挂到新身份 |
| 409 / 1107 | 浏览器已有另一个有效会话，不允许登录表单静默覆盖 |
| 409 / 1203 | 配置版本/状态冲突、唯一性冲突、末位管理员约束；data.reason 区分，刷新后显式重提 |
| 409 / 1206 | 同一 requestId 对应不同有效内容，不自动换新编号重试 |
| 503 / 5001、5002 | 配置/密钥缺失，或数据库/迁移/审计事务失败；不降级本地 JSON/Mock |
| 429 / 待分配 | 登录及敏感密码操作限流；请求主会话分配业务码及 Retry-After 规范，不挪用权限码 |

“未初始化”由公开 capabilities.initialized=false 表达；尝试登录时返回已审核的服务未就绪语义与初始化提示，不创建默认管理员。具体未就绪业务码由主会话统一确认。

## 7. 持久化、事务和密码边界

### 7.1 系统专用模型建议

| 表名提案 | 关键内容/约束 |
|---|---|
| `local_accounts` | 不透明主键、唯一 username、资料、role_id、enabled、identity_revision、last_login；不物理删除 |
| `local_credentials` | 唯一 account_id、版本化密码 KDF 记录、must_change_password、credential_revision/changed_at；任何查询 DTO 不序列化凭据 |
| `local_roles` | 唯一名称、说明、权限编码集合、revision；服务端依赖及职责分离校验 |
| `system_parameters` | 白名单目录和当前值/版本；目录元数据服务端约束，不执行任意代码或路径 |
| `system_state` | 配置 CAS 版本、显式初始化状态；不在 GET 中创建管理账号 |
| `system_operations` | 唯一 actor+operation+request_id、受保护请求指纹、目标/最终版本/变化事实；不存请求原文 |
| `system_audit_events` | 单调 sequence、事件 ID、时间、操作者快照、动作、结果及白名单差异；只追加 |
| `system_audit_archives` | 归档边界、原因、操作者及事件；历史仍存在且可查 |

A 批另提 `local_identity_sessions/local_identity_challenges/local_identity_throttle`；会话令牌仅存高熵令牌 hash，记录关联 ID、代次、期限、撤销原因与账号版本。挑战和节流有界，不由任意用户名无限增行。模型沿用项目 SQLAlchemy 约定，注册、约束及 append-only 防护的正式迁移由主会话统一安排；不抢占 0019 或创建迁移文件。

服务测试通过显式 session_factory 注入到新隔离测试数据库；生产服务仅使用本树 `data/runtime/r2.sqlite`。审计成功事件与账号/角色/参数写入、配置版本和幂等回执同一事务提交；审计失败则回滚该管理写入，不伪称成功。失败登录的节流与脱敏失败事件独立提交后再返回统一拒绝，不因抛异常丢失失败记录。

### 7.2 哈希环境与安全依据

已只读检查主虚拟环境：Python `3.12.4`、OpenSSL `3.0.14`，`hashlib.scrypt` 可调用；未安装 argon2-cffi、bcrypt、passlib、cryptography、Werkzeug。没有安装/升级任何依赖，没有生成哈希、性能测试或安全测试结果。

拟使用已存在的标准库 OpenSSL scrypt 实现，候选 `N=2^17,r=8,p=1`，随机盐至少 16 bytes，摘要 32 bytes，显式有界 maxmem 和哈希并发，不手写 KDF。OWASP 在 Argon2id 不可用时列出该 scrypt 配置；Python 官方文档提供 scrypt 接口及内存控制。成本和登录并发须在获批后以少量真实参数用例核验，不降低参数迎合测试。

- 一手依据：[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[Python 3.12 hashlib.scrypt](https://docs.python.org/3.12/library/hashlib.html#hashlib.scrypt)。
- 密码策略提案：15–128 个 Unicode 标量、UTF-8 最多 1024 bytes；不 trim、不截断、不改变 Unicode 编码；拒绝孤立代理项和 NUL。策略数值待主会话安全配置审核，不是身份源选择待确认。
- 哈希记录包含算法版本/已允许参数/随机盐/摘要；解析先检查参数上界，防止损坏记录导致无界内存或 CPU 消耗；验证采用 bytes 常量时间比较。
- 敏感 requestId 复用比较不能保存明文密码或其无密钥快速摘要。提案为主会话管理的独立密钥 HMAC 指纹，包含操作/主体/目标/规范字段及 key_id；密钥不入数据库、仓库、日志或默认配置。缺少密钥时敏感写入明确拒绝，不能静默降级。该指纹方案随 A/R 一并安全审核。
- 请求 DTO 的 repr、异常、字段校验错误、审计/追踪均不得携带 password/currentPassword/newPassword/initialPassword/operatorPassword、CSRF、Cookie 或会话令牌。请求主会话处理共享 Pydantic 错误包络中的 input 字段脱敏。

### 7.3 首次管理员与正式会话

初始化只接受操作员显式提供登录名和双次 getpass 输入；不通过 argv、URL 或公开环境示例传递口令。空系统才能原子初始化，唯一状态约束防止并发产生两个首任管理者；已初始化只报告事实而不重置、补建或打印密码。初始系统管理权限集合由主会话审核，不能因为用户名为 admin 就授予权限。

正式会话单独 Cookie，与 `radio_integration_session` 分离；HttpOnly、SameSite、Secure/HTTPS 策略和隔离 loopback 测试例外由主会话集中配置。登录后轮换挑战与会话，不把 DTO 的 session_id 当访问令牌；退出/过期/改密/停用/角色变更使旧会话在后续服务端检查中失效，旧行保留。改密后返回已提交事实及 reauthenticationRequired，客户端转重新登录，不能把事后失效伪报为写入失败。

正式身份是 `FORMAL_VERIFIED`，本地适配来源是 LOCAL_PASSWORD；资源/方案/观测仍独立保留 SYNTHETIC_INTEGRATION、UNKNOWN 等业务来源。禁止以“当前业务是构造数据”为由把正式登录降格为演示，或以正式登录为由去掉非实测标识。

## 8. 权限、并发、幂等及取消

- 权限目录由服务端注册表提供；roleId 和 permissions 来自数据库与当前身份版本，不接受客户端自选身份。系统只使用既有 system.view/accounts/roles/parameters/logs/reset；新增本人密码动作的服务权限装配交主会话确认。
- 任意账号停用、换角色、角色权限缩减均在同一写事务内核验：至少保留一个启用、有可用凭据并拥有已审核完整系统管理权限的账号。并发两人互停通过 CAS/事务序列化，不能各自按旧快照放行。
- 保存采用当前配置 baseRevision，只有该版本仍为当前才写；成功更新版本并提交审计/回执。无变化返回 changed=false，不虚构历史变化。日志追加使用独立 auditRevision/sequence，不让每次登录日志使账号表单无意义冲突。
- 普通写入同主体/操作/requestId 且指纹一致重放原回执；不同内容返回 1206。返回丢失时保留原 requestId，查询服务端回执；NOT_FOUND 不等于可判定此前失败，界面明确区分未查到与已确认失败。
- 密码写入不保存完整请求，不自动重试；重新认证后仍可按主体/操作范围查询脱敏回执。停用或失权后不能利用旧回执旁路读取其他主体信息。
- 查询支持 AbortSignal，切页/换筛选/关详情取消旧读取并以请求代次和身份代次丢弃晚到结果。HTTP 工厂在 await 前冻结 id/query/baseRevision/body/required expected fields。
- 写入发出后，关闭抽屉不表示服务端取消事务。busy 时阻止重复提交；结果未知时保留输入与原 requestId，先核实，不生成新事务。普通资料可保留输入，敏感密码字段按提交完成/关闭清空，不能持久化待补密码。
- 会话替换/失权冻结旧表单，不向新身份自动提交；明确放弃后重新加载。系统页已有 allowLeave 保存/放弃/取消机制沿用，并补充密码表单与结果未知状态。
