## 5. 冻结、算法与结果语义

1. 分析必须指定 task_id/plan_id/plan_version/resource_revision/scene_id/scene_version_id/snapshot_hash；服务器按场景保存的 plan_snapshot 与原资源不可变版本核验，不接客户端代填拓扑、算法结论或操作者。
2. 从 raw_snapshot.detail 的 nodes/devices/links/params/frequency/routes/optimization 及 input_snapshot 提取冻结网络、物理设备绑定、已选频点、实际功率/挂高及需求。models/antennas/candidate_site/link_metric 从同一个 ResourceDatasetVersion.snapshot 取得，不读当前 CSV 或任意全局方案。
3. 使用既有 scenario_from_plan/analyze/recommend/build_scenario 的纯算法能力，在本组适配器中组装冻结输入。不得调用会重建网络的 _w3_state，不以 _SCENARIOS 作正式状态源。
4. raw_snapshot.terrain_fingerprint 必须与用于算法的地形数据核对；缺失、无法核对或范围不支持时，拒绝相应计算并给原因，不拿当前 DEM 冒充历史地形，不填假地形。
5. 干扰源按已保存选定版本的 source_row 原样冻结；空选择明确传 []，不能被算法解释为加载全部默认源。必需物理参数缺失则拒绝计算；可选未知字段保持未知，不能沿用旧入口默认 NOISE/OMNI/功率的隐式补齐来冒充原值。
6. 原算法输出 snr_before_db 来自 SNR、snr_after_db 实为受扰 SINR；新 DTO 分别命名 snr_before_db/sinr_after_db，并保留 margin_before_db/margin_after_db。UI 明确是模型预测，不称实测。
7. 每条措施稳定绑定 run_id/measure_id/type/target、冻结配置变化和可用性。preview 只返回实际算出的 impact_after、配置差异、适用条件、缺失原因；coverage/connectivity/delay 等未经完整重算的指标为 null，不补成通过或百分比。
8. 预览在分析 worker 中或另一个明确写操作的计算阶段生成并持久化；本提案选择 worker 中生成，GET 只读取。措施预览只作用于独立副本，不改运行的原始输入、其他措施或已确认方案。

新接口统一前缀 `/api/v1/interference/workbench`；旧 `/api/v1/interference/scenes` 五条保持原契约。成功 HTTP 200/`{code:0,message:"ok",data:...}`；列表分页固定 page/page_size，写入/读取使用 snake_case；额外字段、重复查询键、非有限数字、隐式字符串数值、重复源/目标 ID 拒绝。

### 6.1 DTO 组成

- SourceOption 必有 task_id/plan_id/plan_version/input_version/condition_version/resource_revision/plan_snapshot_id/source/data_origin、current:boolean、eligible:boolean、unavailable_reasons:string[]；不以当前资源拼装完整计划。
- Context 的 capabilities 明确 scene_save/analyze/cancel/preview/adopt_replan 各自 enabled:boolean 与 reasons:string[]；仅能力说明，不代替服务端写操作复核。无权限、无当前确认方案、资源已变、地形不可核对分别表达。
- RunSummary 必有 run_id/task_id/scene_id/scene_version_id/plan_id/plan_version/resource_revision/run_version/state/phase/started_at/updated_at、source_state、adoption_count；状态数量/空页与分页字段严格一致。
- 冻结 source 必有 schema_version=1、各任务/方案/输入/场景/资源版本、scene_snapshot_hash、resource_content_hash、完整场景及计划快照、data_origin/source、实际操作者快照、terrain_fingerprint。Result 包含 analysis_id=run_id、result_hash、affected_nodes/links/regions、summary、measures、unresolved、measure_review；所有引用核对冻结网络。
- Measure 必有 measure_id/type/target_node_id可null/target_link_id可null、priority、title、detail、risk、available、unavailable_reasons、change_set、preview_hash可null；类型仅五类既有措施。算法未给某类可行项时返回不可用原因，不创建可采纳空措施。
- WriteReceipt 必有 request_id/operation/actor_id/task_id/object_type/object_id/accepted_version、changed:boolean、status=ACCEPTED、source_hash、data_origin、accepted_at；派生子身份在相应动作中明确返回。回执不可变，当前运行状态另从对象读取，不能重放时改原回执。
- AdoptionSummary/Detail 必有 adoption_id/task_id/run_id/measure_id/adoption_version/state、planning_request_id、planning_job_id可null、result_plan_id可null、result_plan_state可null、error可null、created_at/updated_at。计算完成但不达标允许真实保存 REFERENCE，页面明确未达标，不能称当前正式方案。

字段完整性、null、关联与实际输入捕获须由前后端共同严格校验；不把新 DTO 强转旧 InterferenceReadView/PlanningResult 或公共 domain 类型。

### 6.2 权限和错误

读要求有效服务端身份及 planning.view+situation.view；场景保存沿用已批准 planning.save；分析/取消要求 planning.execute；采纳/重算要求 planning.execute+planning.save。写操作均检查 CSRF、会话代次、实际操作者及任务可见性，不接客户端 actor/角色/成功状态。权限映射与正式认证入口归主会话。

用户已明确正式认证为本地账号密码，P03 不再把身份源选择列待确认，不自建账户或密码；由 P05/主会话提供会话/角色接口。在正式入口尚未集成时，仅登记实际可验证身份路径，不把联调身份称正式登录。文件 16 内沿用的旧身份源措辞以用户后续明确指示为准。

| HTTP/code | 含义 |
|---|---|
| 422/1001 | 结构、字段、分页、标识、重复源、非有限数、非法措施变化 |
| 401或403/现有110x | 未登录/无权限/CSRF；409/1106为会话变化；复用认证统一映射 |
| 404/2001 | 不存在或对本身份/任务不可见的运行、措施、场景、采纳、回执，统一不泄露归属 |
| 409/1203 | 方案/场景/运行/采纳版本变化、不是当前已确认来源、冻结数据不完整或地形无法核对 |
| 409/1205 | 请求/场景/方案/资源版本不一致或受理时资源已更新 |
| 409/1206 | 相同 request_id 被不同内容、操作或操作者占用 |
| 409/2002 | 当前动作与对象状态不兼容、同任务已有活动分析或子作业冲突；不以成功掩盖 |
| 503/5001、5002、5003 | 配置无效、存储/快照校验失败、资源或所需表尚未准备；不自动初始化或回退文件 |

worker 的算法失败作为 FAILED+具体错误原因保存，数据完整性错误不能包装成“无受扰对象”。不可用措施由 available=false+原因表达；不能把未实现功能伪装成有效动作。

| interference_workbench_runs | run_id主键；task/plan/scene_version/resource引用；request_id唯一；run_version正整数；state/progress/phase/cancel_requested；input_snapshot+source_hash；result_snapshot/result_hash可null；measure/preview快照；实际actor与时间/错误；同任务活动运行通过持久化约束或任务锁复核 |

1. 受理时在同一事务核验当前确认指针、资源指针、已有场景版本/哈希及任务归属，冻结完整输入并保存运行与成功受理回执；不使用另一个 Session 的来源读取充当原子证明。
2. request_digest 包含规范操作/路径、全部校验后输入、实际actor；源集合排序、拒绝重复，正文不静默改写。先核实可见幂等回执再检查当前指针，受理后资源改变仍可重放原回执。
3. 运行和采纳进度以版本 CAS 更新；PENDING→RUNNING→SUCCESS/FAILED，PENDING/RUNNING→CANCEL_REQUESTED→CANCELLED。终态不能被晚到 worker 结果改写。进度查询不承担状态推进、调度或自动恢复。
4. 算法按实际阶段报告进度，阶段间检查取消。内部循环尚无可合作取消点时显示“取消已请求”，不承诺硬终止；确认终态前不宣称停止成功。
5. 进程重启可回读冻结输入、结果和回执。恢复仅由明确的 worker 生命周期入口执行，核验租约/状态版本；失联运行标失败或由显式恢复动作处理，不能 GET 时悄悄重算。
6. 采纳记录本身作为持久化待调度事实，派生稳定 planning_request_id；提交既有规划作业后即使进程中断，也按该请求编号恢复关联，避免重复子作业。需要跨服务同事务保证的部分先交主会话审核，不能以两个独立提交声称原子。
7. 操作回执不可变；对象状态另读。失败校验不生成虚假受理，事务回滚不留下孤立版本/回执。调用方超时保留原request_id先查核，不自动换请求ID重复采纳。
