## 3. 已批准的精确接口

本节应用 HTTP 契约已经 P04-A 审核批准，不是已确认的外部设备协议。三个接口统一包络为 `{"code":0,"message":"success","data":<本节响应>}`；错误为 `{"code":<错误码>,"message":<说明>,"data":null}`。不接受客户端身份字段，不返回虚构操作者或虚构成功回执。

### 3.1 当前规划频点回读

- 方法/路径：`GET /api/v1/resource/frequency-resources`。
- 必填查询：`context=ledger`、`revision=resource-<16位小写十六进制>`。
- 不接收其他查询字段、重复查询键或请求体；`revision` 必须为当前资源版本，过期请求返回 `409/1205`。不开放历史版本查询；历史资源快照仍由底座保留。
- 权限：调用 `integration_identity_service.require(request, "resources.view")`；沿用真实会话校验。显式联调关闭时返回 `401/1101`，不冒充正式认证。GET 不创建业务资源或回执。
- 响应字段完整集合：

```text
revision: ResourceRevision
base_revision: ResourceRevision                 # 与 revision 相同
data_origin: "SYNTHETIC_INTEGRATION"
source: string                                  # 底座原文
content_hash: string                            # 64 位小写十六进制
items: FrequencyItem[]                          # 按 freq_id 升序，包含原禁用点
```

`FrequencyItem` 完整字段集合：

```text
freq_id: Identifier
device_class: "HF" | "VUHF"
center_freq_khz: finite number > 0
bandwidth_khz: finite number > 0 | null
channel_no: integer >= 0 | null
is_available: boolean
occupied_by: string | null
reuse_min_distance_m: finite number >= 0 | null
adjacent_guard_khz: finite number >= 0 | null
note: string | null
```

原始空字符串数值映射为 `null`，非法非空数值或非法可用性字符串按快照损坏拒绝 `503/5002`。本模块只认可可用性字符串 `true`、`false`，不把未知状态映射为可用。既有 `GET /api/v1/resource/frequency-pool?context=planning` 保持现有契约，集成时验证其读取停用后的数据库快照并排除停用点。

### 3.2 停用只读校验

- 方法/路径：`POST /api/v1/resource/frequency-resources/disable/validate`。
- 请求精确字段：

```json
{
  "context": "ledger",
  "revision": "resource-0123456789abcdef",
  "ids": ["FQ-0002", "FQ-0003"]
}
```

- `ids` 为 1 至 50 个不重复 `Identifier`；标识为严格字符串，长度 1 至 120，不含空白和控制字符。禁止类型转换，禁止额外字段。资源版本采用上述严格格式；`context` 只允许 `ledger`。
- 权限：先校验 `resources.view`，再校验拟新增的 `resources.frequency.disable`，第二次 `require(..., writing=True)` 同时核对 `X-Session-Id` 与 `X-CSRF-Token`。虽不写业务数据，沿用现有 POST 预检的会话/CSRF 约束。
- 固定一次当前完整资源快照，先核对版本、全部编号和被选中行；任何编号不存在时整批 `404/1002`。有效请求均返回成功包络，不以缺少频点的部分结果冒充成功。
- 响应字段完整集合：

```text
revision: ResourceRevision                      # 等于请求 revision
base_revision: ResourceRevision                 # 等于 revision
data_origin: "SYNTHETIC_INTEGRATION"
source: string
content_hash: string
selected_ids: Identifier[]                      # 升序
would_disable: Identifier[]                     # 选中且当前为 true，升序
unchanged: Identifier[]                         # 选中且当前为 false，升序
items: FrequencyItem[]                          # 选中项当前值，按 freq_id 升序
impact: {
  resource_revision_will_change: boolean,       # 等于 would_disable 非空
  historical_resources_preserved: true,
  saved_plans_require_recompute: boolean,       # 实际发生资源换版时为 true
  link_impact: "UNKNOWN"
}
```

- `would_disable` 与 `unchanged` 不相交，并集精确等于 `selected_ids`。不计算或声称已获链路级影响；`saved_plans_require_recompute` 表示换版后旧资源方案不再满足当前资源前提，不表示修改、删除历史方案或立即运行重算。
- 只读性：不调用提交函数，不写资源版本、指针或操作回执；重复校验不推进业务状态。校验通过不是保存授权令牌，保存仍在事务内重新核对全部输入。

### 3.3 原子停用保存

- 方法/路径：`POST /api/v1/resource/frequency-resources/disable`。
- 请求精确字段：

```json
{
  "context": "ledger",
  "base_revision": "resource-0123456789abcdef",
  "request_id": "p04-disable-001",
  "ids": ["FQ-0002", "FQ-0003"]
}
```

- `base_revision`、`ids` 约束同预检；`request_id` 使用严格 `Identifier`。拒绝 `is_available`、数值、设备、操作者、来源等额外字段。无需传入预检结果，也不使用客户端结果决定写入。
- 权限：与只读校验相同；保存操作者只能取服务端 `require` 返回的 `account_id`。重放也必须重新通过当前权限、会话和 CSRF 检查。
- 唯一提交入口：直接调用 `resource_dataset_service.commit_device_change(base_revision, request_id, request_digest, actor_id, operation)`，不复制其事务、锁或回执逻辑。`operation(snapshot)` 先核对全部选中项，再仅将 `true` 改为 `false`；抛错时整批回滚，不产生部分修改或失败成功回执。
- 请求摘要精确规范：`content_hash({"operation":"frequency-resource-disable","context":"ledger","base_revision":<请求值>,"request_id":<请求值>,"ids":<升序ids>})`。`request_id` 与 P01 共用底座全局命名空间；操作名防止同一请求号跨业务误重放。重排 `ids` 不改变请求语义。
- 响应字段完整集合：

```text
object_id: "resource-frequency-disable"
request_id: Identifier
base_revision: ResourceRevision
selected_ids: Identifier[]                      # 升序
affected_ids: Identifier[]                      # 与 updated 相同
updated: Identifier[]                           # 本次 true -> false，升序
unchanged: Identifier[]                         # 本次已为 false，升序
items: FrequencyItem[]                          # 选中项保存后值，全部 is_available=false
data_origin: "SYNTHETIC_INTEGRATION"
source: string
warnings: []
changed: boolean                                # 底座附加，等于 updated 非空
revision: ResourceRevision                      # 底座附加
read_revision: ResourceRevision                 # 底座附加，与 revision 相同
```

- `selected_ids` 精确等于请求集合；`updated`、`unchanged` 为其不相交分区。`changed=true` 时新版本不等于 `base_revision`，整个资源版本、当前指针、操作回执同事务提交；`changed=false` 时不创建资源版本、指针不变，但底座持久化一条无变化回执。
- 同身份、同请求号、同摘要重放原回执；即使当前资源随后变化也不能把原回执改成最新内容。回执不是当前资源查询，前端需以回执版本调用回读，若已落后则明确处理 `1205` 并刷新当前资源上下文。
- 同请求号不同内容或不同身份返回 `409/1206`；新请求号携带旧 `base_revision` 返回 `409/1205`。P01 与 P04 不同请求同时修改同一 `base_revision` 时只允许一个发生实际变更的事务成功，另一个版本冲突，不覆盖对方。
- 当前指针换版后旧任务、方案的资源前提失效，已有版本保护继续拒绝以旧资源执行或确认；历史资源及方案快照不变。不自动重算、不重新认证历史方案，不单独维护第二个失效标志。

### 3.4 错误码与 HTTP 状态

| HTTP / code | 精确触发条件 |
|---|---|
| `422 / 1001` | JSON、查询或字段结构错误，额外字段、重复键、空/重复/超量 ids，非严格标识、非法 revision、非 ledger context |
| `404 / 1002` | 版本有效但选中频点不存在；整批拒绝 |
| `401 / 1101` | 显式联调模式未启用；正式身份源仍待确认 |
| `403 / 1104` | 缺少所需页面或频点停用权限 |
| `403 / 1105` | POST 的 CSRF 校验失败 |
| `409 / 1106` | 会话过期、已撤销或 X-Session-Id 不匹配，沿用身份服务口径 |
| `409 / 1205` | 只读版本或新保存请求的 base_revision 已过期 |
| `409 / 1206` | 全局 request_id 被其他内容、操作或身份使用 |
| `503 / 5001` | DATABASE_URL 缺失或资源模式配置非法 |
| `503 / 5002` | 资源快照/频点数据损坏、数据库不可用或提交失败；不回退 CSV |
| `503 / 5003` | 资源未显式初始化或本模块在 file 模式下调用 |

路由需在本模块内部将结构校验、`IdentityError`、`ResourceDatasetError` 转为上述包络；隔离 FastAPI 应用必须验证相同错误包络，不依赖修改主入口才能通过。独立路由前缀为 `/api/v1/resource/frequency-resources`，不导入主 `app`。先检查权限再执行服务读取或提交；路由均不自动初始化资源。
