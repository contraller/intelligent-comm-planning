## 3. 分批行为及精确接口

所有 URL 以下均以 `/api/v1/resource/frequency-resources` 为前缀。延续成功 `code=0/message/data`、失败 `code/message/data=null` 包络；M1/M2 专用契约已获父会话审核，M3 尚为提案，均为应用 HTTP 契约，不是设备协议。

### 3.1 既有接口兼容

- `GET <前缀>?context=ledger&revision=...` 保持完整读取契约，不在旧请求模型中静默接收分页字段。
- `POST <前缀>/disable/validate` 精确请求保持 `{context,revision,ids}`。
- `POST <前缀>/disable` 精确请求保持 `{context,base_revision,request_id,ids}`。
- 版本格式、1–50 唯一严格字符串 ids、原禁用点无变化、unknown/null、来源、字段拒绝与原回执逐字重放继续保持。POST 仍需 resources.view、resources.frequency.disable、真实当前会话及 CSRF。
- 请求摘要和存储继续使用 commit_device_change；写入前在同一底座事务重验全部编号。不同模块同 base_revision 的实际变更只有一方成功，不能覆盖 P01 的新版本。

### 3.2 新增服务器查询

`GET <前缀>/query`；仅需 resources.view，绑定当前会话，读取不写库、不初始化。

完整查询键：

```text
context: literal ledger，必填
revision: ResourceRevision，必填且必须为当前版本
page: integer >= 1，默认 1
page_size: 5 | 10 | 20 | 50，默认 10
search: string，默认空，最长 120，按 freq_id/note 区分大小写字面子串匹配
device_class: HF | VUHF，缺省表示全部
availability: AVAILABLE | DISABLED，缺省表示全部
min_khz / max_khz: finite number > 0，可单侧，双侧时 min <= max
```

拒绝额外/重复键、GET 请求体、非整数页码、非法数值/枚举。固定一次当前资源快照；按中心频率闭区间匹配、上述条件取交集，先全量筛选、按 freq_id 升序，再分页；越界页返回空 items 和真实 total，不静默改变 page。

完整响应字段：`revision,base_revision,data_origin,source,content_hash,page,page_size,total,items`。前五项身份沿用旧 DTO，content_hash 为完整快照哈希，不伪装为分页哈希；items 为旧 FrequencyItem 的完整字段。total 为本次完整筛选集合数量。错误页不替换上次成功数据，但应标记旧内容并禁用写入。

### 3.3 回执核实和历史

`GET <前缀>/operations/{request_id}?context=ledger`：resources.view 和有效会话；只读取当前 account_id 自己的频点操作。缺失、他人操作、同编号的设备操作统一 `404/1002`，不暴露其他对象。不存在不是“未执行”或“失败”的证明；页面可保留原请求并重试。

完整响应字段：

```text
operation: FREQUENCY_DISABLE                 # M3 扩展获批后才加入 FREQUENCY_CHANGES
request_id: Identifier
created_at: 带时区 ISO 8601
receipt: 原始持久化 FrequencyDisableReceipt # 不按当前资源重组或更新
```

`GET <前缀>/operations`：完整查询键 `context=ledger,page=1,page_size=10,search=""`；page/page_size 约束同 query；search 最长 120，仅按 request_id 区分大小写字面匹配。按 created_at 降序、request_id 升序排序，保留微秒精度及后端 Unicode 码点顺序，限定当前操作者及频点操作种类，完整过滤后分页。

完整响应字段：`page,page_size,total,items`。每项精确为 `operation,request_id,created_at,base_revision,revision,changed,selected_count,updated_count,unchanged_count`；计数取原回执，不在历史摘要返回原始整库。点选后按上述请求号接口回读。历史读取不要求旧 revision 等于当前 revision，也不会重新认证旧任务或方案。

实现只读复用 ResourceDatasetOperation 及已有 JSON receipt；核实 actor_id 与 receipt.object_id，损坏回执拒绝 `503/5002`，不补空列表或推断成功。无新表、模型注册或迁移。

### 3.4 M3 已批准契约：启用、新增、改值

本节已获第9节主会话直接批准，原三条接口仍保持窄契约，不改底座和公共角色映射。

拟新增 `POST <前缀>/changes/validate` 和 `POST <前缀>/changes`。预检精确顶层为 `{context:"ledger",revision,changes}`；保存精确顶层为 `{context:"ledger",base_revision,request_id,changes}`。changes 为 1–50 项，同 freq_id 不允许重复或跨动作组合。只允许以下带 kind 的结构：

- `ADD`：`{kind,freq_id,item}`；item 字段为 `device_class,center_freq_khz,bandwidth_khz,channel_no,reuse_min_distance_m,adjacent_guard_khz,note`。center_freq_khz 必填且有限正数，device_class 为 HF/VUHF；其余未知数值允许 null，已填值沿用旧 DTO 的正数/非负整数约束。新编号不得存在，新增频点初始禁用，occupied_by 保持未知，不能创建为已获批准的可用频点。
- `PATCH`：`{kind,freq_id,fields}`；fields 为上述数值及 note 的非空子集，不允许修改 freq_id、device_class、occupied_by 或 is_available；中心频率不能清空，其余允许 null 保留未知。频段边界必须使用当前资源型号中的已知范围校验，不编造频段或设备约束。
- `ENABLE`：`{kind,freq_id}`；不得仅因当前 false 就启用。需能从既有操作/历史证明该点曾为可用且由本系统停用，或为本系统新增的构造频点；原来源预留禁用点及来源证明缺失的点拒绝，主会话确认例外规则前不提供覆盖按钮。原为 true 时返回无变化。

新增权限为 `resources.frequency.maintain`，与原停用权限分开，由主会话映射，不用 resources.edit 或设备权限替代。保存摘要加入 `operation=frequency-resource-changes-v1`，按唯一 freq_id 排序并对字段规范化，identity/base_revision/request_id 仍绑定同一回执；唯一写入口继续为 commit_device_change。

预检完整响应为 `revision,base_revision,data_origin,source,selected_ids,would_change,unchanged,items,impact`；items 为每项动作及变更前/后 FrequencyItem（ADD 的 before=null），impact 精确沿用资源会换版/历史保留/旧方案须重算/link_impact=UNKNOWN。校验全批通过才返回成功，任一无效项整批拒绝。

保存回执完整响应为 `object_id="resource-frequency-changes",request_id,base_revision,selected_ids,affected_ids,updated,unchanged,items,data_origin,source,warnings=[],changed,revision,read_revision`。items 为保存后的完整项；updated/unchanged 为不相交完整分区。回执/历史 GET 在本扩展获批后增加 operation=FREQUENCY_CHANGES，读取前验证真实 receipt.object_id。

新增资料只标记人工构造来源，仍在现有不可变快照/操作回执保留操作事实；不改原 CSV/source_files，不声称用户录入即已获得正式频率许可。具体原预留点封锁、型号能力并集及启用证明规则按第9节已批准回执实施；页面验收仍须宿主联调，不将单测冒充真实页面完成。

### 3.5 错误码、持久化与取消

| HTTP / code | 本组约束 |
|---|---|
| 422 / 1001 | 非法结构、重复键/编号、筛选范围、分页、M3 非法变更或不能证明允许启用 |
| 404 / 1002 | 当前资源缺选中项；回执不存在、非本人或不是频点操作 |
| 401 / 1101、403 / 1104、403 / 1105、409 / 1106 | 沿用可信会话适配的未登录/权限/CSRF/会话更换口径；正式本地账号接线由主会话统一提供 |
| 409 / 1205 | 查询资源版本或新保存 base_revision 过期；旧回执 GET 不按当前版本拒绝 |
| 409 / 1206 | request_id 被其他内容、操作或身份使用；不能自动换请求号掩盖冲突 |
| 503 / 5001、5002、5003 | 配置、数据库/快照或回执损坏、未初始化/文件模式；禁止降级 Mock/CSV |

- M1/M2 无新业务表，不写 GET/预检回执。资源实际变更才生成新版本，无变化仍只记已有底座回执；幂等重放不变更任何历史。
- 提交前取消只关闭预检和确认；提交后点击关闭、AbortSignal 或网络断开不代表事务取消，保留固定请求并进入核实流程。没有“取消已提交资源操作”的业务端点，不实现虚假的撤销成功。
- 同一面板同时仅一个提交；查询使用 AbortController、操作代次及会话 generation 拒绝晚响应。切换筛选/版本使旧预检失效，不能将旧确认套到新选择。
- 超时/断线后状态为 RESULT_UNKNOWN，保留冻结原请求号、base_revision 和完整输入；查询原回执或同请求重放。无权/会话更换时停止旧请求回写，新身份不能接管旧回执或自动重试。
- 待核实请求保留在同一会话的 store；硬刷新后的恢复以“输入原 request_id 核实”及本人历史为服务器事实入口，不把浏览器持久化数据作为成功证据。离开前明确存在待核实操作，不静默显示已取消。
