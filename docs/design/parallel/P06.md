## 3. 权限、输入及公共结构

### 3.1 权限与会话

- 全部接口仅在 `FRONTEND_INTEGRATION_DEMO=1`、`RESOURCE_DATASET_MODE=database` 下开放；这是构造联调受理契约，不是正式认证或真实设备协议。
- P06 路由要求已有有效 `radio_integration_session` Cookie 和匹配的 `X-Session-Id`；缺 Cookie 返回 401/1101，不使用无 Cookie 默认规划员作为持久化请求身份。
- 全部接口校验 `resources.view`。两个 POST 另校验现有 `resources.device.edit` 及 `X-CSRF-Token`；沿用 `integration_identity_service.require`，不增加或伪造权限。目前该写权限仅给联调编辑者，规划员、审核者不能受理请求。
- 配置详情、历史仅返回当前 `account_id` 自己提交的记录；跨身份详情按不存在返回，不透露另一身份、原请求或回执。此限制不声称已实现正式租户隔离。
- 认证、会话、权限和 CSRF 检查先于幂等重放。客户端不得提交 actor、角色、时间、回执状态或执行结果。

### 3.2 输入与版本

- HTTP 前缀为 `/api/v1`，模块 schema 版本固定为 `device-configuration-a1`，不代表设备协议版本。所有请求/响应为 UTF-8 JSON，统一包络为 `{code, message, data}`，成功 `code=0`、HTTP 200。
- `context` 只允许 `ledger`；`gis` 接入另行审核。未知字段、未知查询参数、重复查询参数、空白/控制字符编号均拒绝，不静默丢弃。
- `device_id`、`model_id`、资源版本复用现有 `Identifier`：严格字符串，长度 1–120，不含空白或控制字符。`request_id` 为路径安全字符串，格式 `[A-Za-z0-9][A-Za-z0-9._:-]{0,119}`；context、validate、history 是保留路径编号，返回 422/1001，避免详情与静态路由冲突。
- `values` 精确为 `{tx_power_dbm: number, work_freq_khz: number}`，两项必填；数值必须有限，拒绝布尔值、数值字符串、null、NaN、Infinity。频率单位 kHz，功率单位 dBm，不暗中换算。
- 读取客户端指定的当前资源版本。型号必须与该版本中的设备 `model_id` 一致；在架判定沿用既有 `availability` 规则，旧基线未给字段时按 ACTIVE，显式非法值拒绝。
- 新请求功率不得超过该型号 `tx_power_max_dbm`；频率须大于 0 且在 `[freq_min_khz, freq_max_khz]` 内，端点允许。不编造最低功率、功率档位、步进、带宽或频点许可；型号数值缺失、损坏或上下限倒置时拒绝受理。
- 不沿用台账原值舍入超限豁免来批准新配置请求。未提供档位资料时不推测离散功率档位；型号范围校验不代表频率许可或干扰合格。
- `ports`、`current_work_mode`、`currentWorkMode`、`mode`、`scenario`、`presetVersion`、`retryOf` 及其他未约定字段均返回 422/1001。端口和模式即使传入看似常用值也不予受理。

### 3.3 精确响应 DTO

下列类型只在本模块定义，不复用现有前端执行结果类型。对象字段按此清单解码，未知 schema 版本拒绝。

| 名称 | 精确字段 |
|---|---|
| `Values` | `tx_power_dbm:number`、`work_freq_khz:number` |
| `SourceValues` | `tx_power_dbm:number或null`、`work_freq_khz:number或null`；仅来自资源台账，不表示设备实测值 |
| `DeviceSnapshot` | `device_id:string`、`node_id:string`、`model_id:string`、`availability:"ACTIVE"`、`source_values:SourceValues` |
| `ModelConstraints` | `model_id:string`、`freq_min_khz:number`、`freq_max_khz:number`、`tx_power_max_dbm:number` |
| `Provenance` | `data_origin:"SYNTHETIC_INTEGRATION"`、`resource_source:string`、`source_files:Record<string,{path:string,sha256:string}>`；逐项保留资源快照原标识和来源清单，不重写成实测来源 |
| `Actor` | `account_id:string`、`display_name:string`、`role_id:string`、`identity_revision:string`、`integration_mode:true`；服务端身份快照，不保存 Cookie、令牌或 CSRF |
| `Context` | `schema_version:"device-configuration-a1"`、`context:"ledger"`、`resource_revision:string`、`resource_content_hash:string`、`device:DeviceSnapshot`、`model:ModelConstraints`、`provenance:Provenance`、`protocol:{port_options:null,mode_options:null,confirmation:"待确认"}` |
| `Acceptance` | `schema_version:"device-configuration-a1"`、`configuration_id:string`、`request_id:string`、`request_digest:string`、`context:"ledger"`、`device_id:string`、`model_id:string`、`base_revision:string`、`resource_content_hash:string`、`requested_values:Values`、`device_snapshot:DeviceSnapshot`、`model_constraints:ModelConstraints`、`provenance:Provenance`、`actor:Actor`、`accepted_at:string`、`status:"ACCEPTED"`、`receipt_scope:"SYSTEM_ACCEPTANCE"`、`dispatch_status:"NOT_DISPATCHED"`、`device_execution_status:"UNKNOWN"`、`applied_values:null`、`online:null`、`effective:null`、`device_reported_at:null`、`message:string` |
| `HistoryItem` | 从同一回执投影的 `configuration_id`、`request_id`、`device_id`、`model_id`、`base_revision`、`requested_values`、`accepted_at`、`status:"ACCEPTED"`、`receipt_scope:"SYSTEM_ACCEPTANCE"`、`dispatch_status:"NOT_DISPATCHED"`、`data_origin:"SYNTHETIC_INTEGRATION"` |

`configuration_id` 由服务端生成，格式 `DC-` 加 32 位小写十六进制 UUID；摘要均为 64 位小写 SHA-256。`accepted_at` 为服务端 UTC RFC3339 时间，带 `Z`，幂等重放不更新时间。`Acceptance.message` 固定为“配置请求已持久化，系统受理；未下发，设备执行与生效状态待确认”。

本批受理状态保持 `ACCEPTED`，无自动推进、后台下发、模拟失败和成功分支。不提供客户端补填回执接口。`applied_values`、`online`、`effective`、`device_reported_at` 必须保留 null。

## 4. 精确接口清单

下列 5 个接口已获 P06-A 审核批准；静态 `/context`、`/validate`、`/history` 必须先于 `/{request_id}` 注册。

| 方法与完整路径 | 精确请求 | 成功 `data` | 权限与幂等 |
|---|---|---|---|
| `GET /api/v1/device-configurations/context` | 查询必填 `context=ledger`、`device_id`、`revision`，无请求体 | `Context`；资源版本必须等于 `revision` | 有效会话 + resources.view；只读，不生成配置记录 |
| `POST /api/v1/device-configurations/validate` | JSON 精确字段：`schema_version`、`context`、`base_revision`、`device_id`、`model_id`、`values`，均必填 | `{valid:true,context:Context,requested_values:Values}` | 同上 + resources.device.edit + CSRF；只读，不保留回执，不返回预生成结果 |
| `POST /api/v1/device-configurations` | validate 同样字段另加必填 `request_id` | 完整 `Acceptance` | 同上 + resources.device.edit + CSRF；提交成功必须持久化，同一 request_id 重放冻结回执 |
| `GET /api/v1/device-configurations/history` | 查询必填 `context=ledger`；可选 `device_id`，`page` 默认 1、整数且 >=1；`page_size` 默认 20、整数且 1–100 | `{schema_version:"device-configuration-a1",context:"ledger",items:HistoryItem[],total:整数,page:整数,page_size:整数}` | 有效会话 + resources.view；限定当前 actor，可按设备编号精确筛选，摘要只读 |
| `GET /api/v1/device-configurations/{request_id}` | 路径为 request_id；查询必填 `context=ledger`，无请求体 | 原始 `Acceptance`，支持 POST 超时后按原 request_id 核实 | 有效会话 + resources.view；限定当前 actor，只读 |

validate 不返回 `valid:false` 的成功包络：不合格输入统一按下表返回失败，不插入历史。submit 重新核验，不能仅相信客户端或之前 validate 的结果。

历史按 `accepted_at DESC, configuration_id DESC` 稳定排序；空页或不存在的设备筛选返回空数组与实际 total，不补造记录。分页不是跨请求冻结游标，并发新增时后续页可变化。历史与详情不要求当前资源仍等于受理时版本；设备随后下架或资源换版后仍按冻结内容回读，不拼接最新参数，不读取或推导设备当前状态。

## 5. 错误码和拒绝语义

失败包络 `{code:下表代码,message:原因,data:null}`；仅 422/1001 的字段校验错误可返回 `data:{issues:[{field:string,message:string}]}`。不回传原始异常、SQL、Cookie 或另一身份的内容。

| HTTP / code | 触发条件 |
|---|---|
| `401 / 1101` | 联调模式关闭，或缺少已建立的联调 Cookie |
| `403 / 1104` | 缺 resources.view 或 POST 缺 resources.device.edit |
| `403 / 1105` | POST CSRF 缺失或不匹配 |
| `409 / 1106` | 会话无效、过期、已轮换，X-Session-Id 缺失或与当前会话不匹配 |
| `422 / 1001` | schema/context/字段/类型/标识/分页非法，未约定端口或模式，功率或频率不符合型号约束 |
| `404 / 1002` | 当前指定设备不存在，或请求详情不存在/不属于当前 actor |
| `409 / 1203` | 设备已下架，或请求 model_id 与冻结设备型号不一致 |
| `409 / 1205` | context/validate/新提交的资源版本已变化；先查幂等回执再核验新请求资源版本 |
| `409 / 1206` | 相同 request_id 被不同请求内容或不同 actor 使用；不得覆盖原记录 |
| `503 / 5001` | 数据库配置缺失或无效 |
| `503 / 5002` | 数据库操作失败、资源快照/型号约束损坏、并发事务失败且未取得已提交回执；不伪装成功 |
| `503 / 5003` | 非 database 模式、资源尚未初始化或本模块所需表尚未迁移；不自动初始化和降级文件 |

本表复用既有通用业务码，无新增独占码段。幂等唯一约束冲突应回滚后重新读取：同内容同身份返回原回执，内容/身份不符 1206；无已提交回执则 5002 并可重试原请求。

## 6. 持久化、幂等与数据库建议

- 建议新增单表 `device_configuration_requests`，不预占 Alembic 号、不改旧迁移、不注册共享模型。迁移号、单 head 顺序和正式注册由主会话安排。
- 建议列：`request_id` 为字符串主键；`configuration_id` 字符串非空唯一；`schema_version`、`request_digest`、`actor_id`、`device_id`、`model_id`、`base_revision`、`resource_content_hash` 为非空字符串；`accepted_at` 为带 UTC 语义的非空时间；`receipt` 为非空 JSON。索引建议 `(actor_id, accepted_at, configuration_id)`、`(actor_id, device_id, accepted_at, configuration_id)`；索引名称随正式迁移由主会话核对。
- receipt 一次写入完整 Acceptance，包含请求值、设备/型号冻结投影和原资源来源清单；HistoryItem 从同一记录投影。此表不是第二套可编辑设备资源表，也不包含状态快照或遥测表。
- 规范化请求精确包含 `schema_version`、`context`、`base_revision`、`device_id`、`model_id`、`values`；数值按同一有限数值规则归一，1 与 1.0 等值、负零按零处理，再按固定键序 JSON 计算摘要。actor 单独比较，request_id 为幂等键；不把 Cookie、CSRF、当前会话代次和服务器时间放入业务摘要。
- 每次 submit 先校验权限和结构，再查已持久化 request_id；同 actor、同摘要返回原始回执，不创建第二条记录、不更新 accepted_at，不因为资源随后变化或设备下架而否认已受理事实。换会话后只要仍是同 account_id 且具备权限即可重放。
- 首次受理在一个写事务内读取当前资源指针及其不可变快照，校验版本、来源完整性、设备在架、型号和数值，再插入请求与回执。SQLite 须先取得写事务锁再读取指针，使资源维护和首次受理串行化；只读资源模型，不更新资源表或用共享保存入口制造资源版本。其他数据库方言的锁语义待确认。
- 资源合法性读取可复用已有校验逻辑；不得从请求外缓存或先行 validate 快照直接确认。两请求并发使用同 request_id 时，由数据库唯一约束保证至多一条记录，事务异常不保留半条回执。
- 只在事务提交成功后返回受理；拒绝请求不形成“已受理”历史。提交响应丢失后，客户端保留原 request_id 先查详情，必要时重发同内容，不自动创建新编号。
- GET 不初始化数据库、资源、会话或设备状态，不启动任务、不写业务记录。历史回读不依赖内存任务字典；SQLite 关闭重开后仍应返回同一回执。
- collab.sqlite 是本组开发/真实 HTTP 库；模块测试在本树 data/runtime/tmp 下每轮新建独立 SQLite，仅为所需模型显式建表，不在 collab.sqlite 重建或清空表，不删除已有库和证据。此前“只能有一个库”的解释已按主会话澄清更正。不得导入主 app 触发共享装配，不自动在真实服务启动时 create_all。生产迁移前不可把该模块标为正式接口已完成。

## 7. 前端边界与共享集成请求

- 基线 `src/types/device-configuration.ts` 的 `ConfigurationStatus` 只有 RUNNING/SUCCEEDED/FAILED，`ConfigurationValues` 强制 currentWorkMode，现有校验依赖教学 scenario/preset。不能表示本批语义，不得将 ACCEPTED 转为 SUCCEEDED 或 RUNNING，不调用旧 Mock 校验来生成模式。
