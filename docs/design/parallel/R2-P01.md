## 契约与分批边界

1. GET /api/v1/resource/import/template：context=ledger/gis、revision、format=csv/xlsx、kind=nodes/devices/interference_sources，返回带来源说明的服务端模板。
2. POST /api/v1/resource/import/preview：context、base_revision、kind、file={name,base64}；最大5MiB、5000业务行，严格UTF-8 CSV/XLSX；服务端完整解析、跨表校验，返回原请求对应签名、逐行NEW/UPDATE/UNCHANGED/差异、issues/warnings和真实完整candidate/changes。预检不写资源或回执。
3. POST /api/v1/resource/import/commit：相同原始文件与签名加request_id；服务器在统一底座写锁内重新解析、校验、核对版本和内容签名，整批原子保存，返回轻量资源回执。不得相信客户端candidate/changes，不创建预览令牌主库或临时文件，无新增迁移。
4. GET /api/v1/resource/edit-context：按当前版本返回真实完整资源编辑选项及当前快照；POST /api/v1/resource/workspace/changes：严格限定站点/设备/干扰源/候选配置的增量保存，不删除、不隐式修改状态或原件，沿用不可变版本和幂等回执。GIS及新增入口复用此底座，不另造资源库。
5. 实例历史/恢复、候选专用导入及原页面其他资源动作先复核精确需求；对应内部扩展先在本记录追加。端口/真实模式协议不能由模板编造。

权限使用专项 resources.import、resources.create、resources.workspace.edit（均依赖resources.view）；仅显式联调编辑者按所需动作增加，不授予不受限resources.edit。正式用户映射仍待身份源确认。GET/POST均校验既有会话，写入及预检绑定CSRF；来源统一SYNTHETIC_INTEGRATION。资源变更后旧方案标记过期但保留，不自动重算。
