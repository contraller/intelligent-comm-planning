## 本批范围

指定已保存方案的冻结网络、单链路静态详情和业务路径只读投影。支持历史方案回读并标记来源变化；不把当前资源补入旧快照、不从任意任务选择最新方案。指标只能来自冻结结果，算法预测与实时观测分开，未提供数据保留 null/缺失状态。

不包含 GIS 资源编辑、实时观测、覆盖重算、DEM/MVT 改动、设备下发、优化算法调整、正式认证或主页面接线。

## 接口契约提案

所有接口为 GET，前缀 /api/v1/gis/plans/{plan_id}，沿用 code/message/data 包络；context 只接受 gis，task_id 必填。

| 路径 | 请求 | 响应 data |
|---|---|---|
| /network | context、task_id；可选 snapshot_id 用于重读校验 | plan_id/task_id、snapshot_id、input_version/condition_version/resource_revision、state/source_changed、data_origin/source、冻结节点/设备/链路及需求/路由身份 |
| /links/{link_id} | context、task_id、snapshot_id 必填 | 同一来源身份、链路端点与设备绑定、频段/频点/备用标识、冻结参数；观测字段明确未提供，不伪造 SNR/BER/丢包率等实测值 |
| /paths | context、task_id、snapshot_id 必填；可选 demand_id | 同一来源身份、匹配需求与主备路径的节点/链路序列；从 configuration.routes 和 input.demands 投影，不重新求路由 |

权限：复用 integration_identity_service.require 的 situation.view；仅显式联调模式，不假装已完成正式多用户数据隔离。无数据库不静默读取旧 HTML 或 Mock。

只读接口不设置写入幂等号；同一 plan_id/task_id/snapshot_id 的冻结业务内容应相同，source_changed 等当前有效性标识单独展示。读取不更新指针、提交任务、生成资源版本或写审计回执。

错误沿用项目语义：422/1001 非法参数；404/1002 指定链路/需求不存在；404/2001 方案不存在或任务不匹配；409/1203 snapshot_id 不一致或冻结结果结构无法安全投影；401/1101 未开启联调；403/1104 无权限；503/5001 数据库未配置、503/5002 数据库操作失败。对象标识长度遵循既有 Identifier。损坏结果不能返回零链路成功。

前端提供独立工厂和专用 DTO，不接管共享 http.ts，也不要求既有 LinkDetailContext 用0填充缺失带宽。严格核对请求任务/方案/快照、唯一ID、节点设备关联、路由连通顺序和需求归属。

### 响应字段与关联边界

三类 data 均带 identity：plan_id、task_id、snapshot_id、input_version、condition_version、resource_revision、state（SAVED/REFERENCE/CONFIRMED）、source_changed（布尔）、data_origin（SYNTHETIC_INTEGRATION）、source（SR4）。snapshot_id 必须取已保存 result_snapshot.snapshot_id，不能生成另一标识掩盖缺失快照。其余版本来自同一 PlanningPlan 行。

- network 的其他字段为 nodes、devices、links、demands、routes、paths_state、paths_message。所有数组元素仅取本方案的 result_snapshot、input_snapshot；不查询当前节点或设备补齐字段。
- Node：id、name、coordinate（经纬度两元素有限数值）、status（NORMAL/FAULT/OFFLINE/null）、alert（布尔/null）。缺少已冻结坐标、ID或名称拒绝投影；未提供状态/告警为null。
- Device：id、station_id、model_id、device_class（HF/VUHF）、frequency_khz、tx_power_dbm、antenna_height_m；后三项是冻结配置值或null，不是设备实测状态。设备所属节点必须存在。
- Link：id、a、b、device_a、device_b、device_class、frequency_khz、backup、planned_state。端点和设备必须存在且所属站点一致；频点缺失为null，planned_state从结果复制，缺失为null，不推断实时通断。
- Demand：id、source_id、target_id、source_device_id、target_device_id、service、mandatory、required_rate_kbps、min_reliability；后四项只复制已冻结值，可空字段用null。非空设备端点必须归属于需求端点站点。
- Route：id、demand_id、node_ids、link_ids、backup。路径长度须满足节点数=链路数+1、逐条端点连贯，起止与需求一致；相同需求的主/备路径明确区分。路径不得引用本方案以外的节点、链路或需求。
- paths_state为ready/missing：存在完整且关联正确的路径资料时ready；结果明确缺少路径资料时missing并返回非空paths_message，不将未提供资料伪装成已计算零条路径。结构已提供但引用损坏时409/1203，不静默删坏记录。
- links/{link_id} 返回identity、link、endpoint_devices（两端冻结设备）、demand_ids、route_ids、observation（state=missing、message非空、samples=[]）。不提供实时SNR/BER等值，不从计划链路等级推断观测结论。
- paths 返回identity、demands、routes、paths_state、paths_message；指定demand_id时仅返回该需求和对应路径，不重新寻路，不改变主备。

前端字段可在专用DTO内采用camelCase，但仅在新适配器边界映射；snake_case线上契约不要求共享domain类型扩展。网络和详情的重复ID、非有限数值、错归属和错误路径均拒绝。
