## 3. 精确接口契约

以下为已获 P03-A 审核的契约。服务端 JSON 使用 snake_case，成功为 HTTP 200、`{"code":0,"message":"ok","data":...}`；失败使用同样的 `code/message/data` 包络，`data=null`，不泄露其他任务或操作者对象。请求体、查询参数拒绝未列字段和重复查询键；不接受字符串冒充数字、布尔值冒充整数。时间为服务端生成的 UTC ISO 8601 字符串。

### 3.1 保存版本

`PUT /api/v1/interference/scenes/{scene_id}`

路径 `scene_id`：非空字符串，最长 120 字符，不含空白、控制字符及正反斜杠（单个 URL 路径段）；由调用方生成，作为首批创建幂等重试时稳定的对象身份。JSON 所有字段必填，额外字段返回 422：

| 字段 | 精确类型及约束 |
|---|---|
| `request_id` | string，1-120 字符，无空白、控制字符及正反斜杠；需用于回执 URL 路径 |
| `task_id` | string，同上 |
| `plan_id` | string，同上；必须属于 `task_id` |
| `plan_version` | string，`V` 加正整数，与 `PlanningPlan.version_no` 一致 |
| `resource_revision` | string，1-120 字符；必须等于该方案及当前资源指针的版本 |
| `base_scene_version_id` | string 或 null；创建只能为 null，更新必须等于该场景最新版本 ID；字符串最长 40 字符且无空白和控制字符 |
| `name` | string，1-60 字符，无首尾空白，不允许纯空白 |
| `note` | string，0-500 字符，允许空串，不接受 null |
| `interference_ids` | string[]；元素满足 1-120 字符标识规则、不得重复，均存在于指定资源的 `interference_source.csv`；允许空数组 |

新请求成功响应 `data` 为下文的 `SceneReceipt`。相同操作者相同请求重放返回原持久化回执；不会根据新来源重建结果。新 `request_id` 且内容与当前版本一致时，返回指向既有版本的 `changed=false` 新回执，不新增场景版本。新版本回执 `changed=true`。来源版本、方案身份或冻结内容变化不认定为无变化。

保存校验：方案须为本任务的 `PlanningCurrentPlan`，`state=CONFIRMED`、`source=SR4`；校验方案版本、资源版本、冻结拓扑、需求和路由引用完整性。`raw_snapshot` 缺失时拒绝，不读取当前资源节点或算法文件拼补历史方案。来源选择与场景写入必须在一致的事务时点核对，并在隔离测试中验证并发冲突；不能以进程内锁宣称持久化并发安全。

### 3.2 场景目录

`GET /api/v1/interference/scenes`

查询仅接受：`task_id` 必填；`page` 正整数默认 1；`page_size` 整数 1-100 默认 20；`search` 可省略，为最长 120 字符的字面子串，匹配该任务下场景 ID 或最新版本名称，`%/_` 不作通配符。

响应 `data={items:SceneSummary[],total:int,page:int,page_size:int}`。只列各场景最新版本；按 `saved_at DESC,scene_id ASC` 稳定排序，空目录和超出页为 `items=[]`。列表只读已存在记录，不要求任务当前仍有确认方案。

### 3.3 场景详情及指定不可变版本

`GET /api/v1/interference/scenes/{scene_id}`

查询仅接受：`task_id` 必填；`version_id` 可省略。省略时读取该场景最新版本；提供时只读属于该任务、该场景的指定版本。列表打开详情必须传列表返回的 `version_id`，避免并发保存后读到不同版本。

响应 `data={version:SceneVersion,source_state:{state:"CURRENT"|"HISTORICAL"|"UNKNOWN",reasons:string[]}}`。`version` 全部来自持久化冻结数据；`source_state` 是额外的只读时点说明，不写回版本，也不纳入持久化回执。方案已切换或资源更新返回 `HISTORICAL`，来源指针无法完整核验返回 `UNKNOWN` 并给原因，不阻止完整历史快照回读；冻结数据损坏按 5002 拒绝，不作为未知数据成功返回。

### 3.4 版本历史

`GET /api/v1/interference/scenes/{scene_id}/versions`

查询仅接受：`task_id` 必填；`page/page_size` 与目录一致。响应 `data={items:SceneSummary[],total:int,page:int,page_size:int}`，按 `version_no DESC`；仅查询该场景版本，不带完整拓扑。不存在场景与跨任务访问均为 404/2001。

### 3.5 持久化回执

`GET /api/v1/interference/scene-operations/{request_id}`

查询仅接受 `task_id`、`scene_id`，均必填。响应 `data=SceneReceipt`，只返回当前操作者在指定任务和场景下的成功回执。不存在、跨任务、跨场景或跨操作者均为 404/2001。未提交成功的请求不生成成功或失败回执；404 只表示当前没有可见成功回执，不证明其他在途请求已经失败。

### 3.6 完整响应类型

`SceneSummary` 字段全部必有：`scene_id:string`、`task_id:string`、`version_id:string`、`version_no:int>=1`、`name:string`、`plan_id:string`、`plan_version:string`、`resource_revision:string`、`source_count:int>=0`、`snapshot_hash:string`、`data_origin:string`、`saved_at:string`。标识、名称和版本约束同保存；哈希为 64 位小写十六进制 SHA-256。

`SceneVersion` 为 `SceneSummary` 加以下全部字段：

| 字段 | 类型及语义 |
|---|---|
| `schema_version` | 固定整数 1 |
| `note` | string，保存的说明 |
| `previous_version_id` | string 或 null，创建为 null，更新指向前一版本 |
| `saved_by` | string，服务端身份的 account_id，不接受客户端代填 |
| `resource_content_hash` | 该资源版本已有的 64 位内容哈希，不生成第二套资源版本号 |
| `source` | 原资源版本的来源说明 string，原样保存 |
| `interference_ids` | 排序后的唯一 string[]；对应冻结源的相同顺序 |
| `interference_sources` | `{interference_id:string,source_row:Record<string,string>}[]`；`source_row` 深拷贝已有资源表行，含相同 `interference_id`，保留原始字段与空字符串，不经过补零投影 |
| `plan_snapshot` | 下文定义的完整冻结对象，非当前资源拼接投影 |

`plan_snapshot` 必有：`task_id`、`plan_id`、`plan_version`、`input_version`、`condition_version`、`resource_revision`、`source`（均 string，`source=SR4`），以及 `input_snapshot`、`raw_snapshot`（原存储 JSON 对象的完整深拷贝）。`raw_snapshot` 必有 `solution_id:string`、`summary:object`、`detail:object`；`detail.nodes/devices/links` 为非空对象数组，`detail.routes.routes` 为非空数组，引用须与冻结节点、设备、链路及输入需求一致。额外已有原始字段原样保留，不以空对象代替缺失数据。`terrain_fingerprint` 为原值或 null，缺失按未知处理，不生成新地形指纹、不加载当前 DEM；地形未知不宣称后续可重算。

`snapshot_hash` 对 `schema_version/name/note/plan_snapshot/resource_revision/resource_content_hash/data_origin/source/interference_ids/interference_sources` 的规范化 JSON 计算，不包含服务器 ID、版本序号、时间或动态 `source_state`。GET 核验冻结内容哈希后回读。

`SceneReceipt` 字段全部必有：`request_id:string`、`operation:"SAVE_INTERFERENCE_SCENE"`、`status:"SUCCEEDED"`、`actor_id:string`、`task_id:string`、`scene_id:string`、`base_scene_version_id:string|null`、`version_id:string`、`version_no:int>=1`、`plan_id:string`、`plan_version:string`、`resource_revision:string`、`snapshot_hash:string`、`data_origin:string`、`changed:boolean`、`created_at:string`。回执的 `created_at` 是该操作提交时间；无变化保存时不改旧版本的 `saved_at`。响应不添加 `analysis_id/job_id/plan_result`。

## 4. 权限、版本及持久化幂等

- GET 均调用已有 `integration_identity_service.require(request,"planning.view")`；PUT 调用 `require(request,"planning.save",writing=True)`，校验现有 Cookie/`X-Session-Id`/`X-CSRF-Token`。权限采用现有规划查看/保存能力，不新造默认账号、不放宽角色、不直接编辑权限目录。正式身份及任务租户隔离仍待 P05 与主会话确认；本批不能标为正式鉴权完成。
- 各读取均按 `task_id` 验证对象归属；回执另外验证实际 `account_id`。调用方不得传 `actor_id/saved_by/status/changed`。
- 幂等键是 P03 回执表内唯一 `request_id`；摘要覆盖操作名、规范化路径 scene_id、task_id、实际 actor_id 和完整校验后请求内容，不含会话 token。干扰源选择按集合排序；重复元素先拒绝。JSON 使用稳定键序、UTF-8、拒绝 NaN/Infinity；不静默改写正文字符串。
- 通过身份、权限和结构校验后，先查持久化幂等回执，再检查当前资源/方案/场景版本。同操作者同内容即使场景已更新或资源已切换，也返回原回执；同键异内容或另一操作者占用同键返回 409/1206，不泄露原对象。
- 场景最新版本指针采用 `base_scene_version_id` 条件更新；版本序号单调增长。不同请求同时写同一基础版本，最多一条生成新版本；失败事务不留下版本或回执。相同请求的跨线程、跨 Session 重放仅一条回执。
- 新场景、不可变版本、最新指针和成功回执同事务提交；无变化保存只新增回执。唯一约束/竞争回查必须重验操作者和摘要，不能把任意 IntegrityError 当作成功。SQLite 锁冲突回滚后返回 409/1203，调用方保持同 request_id 核实或重试。
- 不修改 `PlanningCurrentPlan`、`ResourceDatasetCurrent`、`ResourceDatasetVersion` 或主资源干扰源。既有资源表和冻结方案是依赖，P03 不建立资源主库。

## 5. 错误码

| HTTP / code | 精确场景 |
|---|---|
| 422 / 1001 | 缺字段、额外字段、重复查询键、类型/长度/分页不合法、重复干扰源 ID、所选源不在指定资源版本 |
| 401 / 1101 | 显式联调模式关闭；沿用现有身份入口，不提供替代登录 |
| 403 / 1104 | 无所需规划权限 |
| 403 / 1105 | CSRF 缺失或不匹配 |
| 409 / 1106 | 会话失效或 X-Session-Id 不匹配 |
| 404 / 2001 | 任务/方案/场景/版本/可见回执不存在或归属不符；无当前确认方案 |
| 409 / 1203 | 场景基础版本冲突、已存在场景却以 null 创建、方案版本不符/非当前确认/非 SR4、缺失或引用不完整的冻结拓扑、写事务锁冲突 |
| 409 / 1205 | 请求、方案、当前资源指针三者资源版本不一致 |
| 409 / 1206 | request_id 对应不同摘要或实际操作者；复用既有资源维护冲突码 |
| 503 / 5001 | DATABASE_URL 未配置或数据库配置无效 |
| 503 / 5002 | 数据库不可用、持久化内容或哈希损坏；不回退文件/Mock |
| 503 / 5003 | 资源尚未初始化或本批所需新表未迁移；GET 不自行初始化 |

前端专用适配器复用 `ApiError`，将 1001/2001/1203/1205/1206 映射为 `VALIDATION_ERROR/NOT_FOUND/VERSION_CONFLICT/RESOURCE_VERSION_CHANGED/REQUEST_CONFLICT`；认证、CSRF、会话及 5xxx 原错误保留，不吞错误。成功包络但字段、归属、版本、计数或哈希格式不符，抛 `INVALID_RESPONSE`。

## 7. 数据库建议、依赖与共享变更请求

### 7.1 与实际模型一致的 DDL 建议

以下为 SQLAlchemy SQLite 方言编译出的模型 DDL，仅供总集成编写统一迁移；未在开发库或主库执行，不含迁移编号。注册沿用现有 `database.Base`，不存在第二套 P03 元数据；Alembic 模型装载处需显式导入 `InterferenceScene`、`InterferenceSceneVersion`、`InterferenceSceneReceipt`。现有 task/job/plan/resource 模型须先进入同一 metadata，依赖迁移由主会话排定。

```sql
CREATE TABLE interference_frontend_scenes (
    scene_id VARCHAR(120) NOT NULL,
    task_id VARCHAR(120) NOT NULL,
    latest_version_id VARCHAR(40) NOT NULL,
    latest_version_no INTEGER NOT NULL,
    PRIMARY KEY (scene_id),
    CONSTRAINT ck_interference_scene_latest CHECK (latest_version_no >= 1),
    FOREIGN KEY(task_id) REFERENCES planning_tasks (task_id)
);
CREATE INDEX ix_interference_frontend_scenes_task_id
    ON interference_frontend_scenes (task_id);

CREATE TABLE interference_frontend_scene_versions (
    version_id VARCHAR(40) NOT NULL,
    scene_id VARCHAR(120) NOT NULL,
    task_id VARCHAR(120) NOT NULL,
    plan_id VARCHAR(40) NOT NULL,
    resource_revision VARCHAR(120) NOT NULL,
    version_no INTEGER NOT NULL,
    name VARCHAR(60) NOT NULL,
    snapshot JSON NOT NULL,
    snapshot_hash VARCHAR(64) NOT NULL,
    saved_by VARCHAR(120) NOT NULL,
    saved_at DATETIME NOT NULL,
    PRIMARY KEY (version_id),
    CONSTRAINT uq_interference_scene_version UNIQUE (scene_id, version_no),
    CONSTRAINT ck_interference_scene_version CHECK (version_no >= 1),
    FOREIGN KEY(scene_id) REFERENCES interference_frontend_scenes (scene_id),
    FOREIGN KEY(task_id) REFERENCES planning_tasks (task_id),
    FOREIGN KEY(plan_id) REFERENCES planning_plans (plan_id),
    FOREIGN KEY(resource_revision) REFERENCES resource_dataset_versions (revision)
);
CREATE INDEX ix_interference_frontend_scene_versions_scene_id
    ON interference_frontend_scene_versions (scene_id);
CREATE INDEX ix_interference_frontend_scene_versions_task_id
    ON interference_frontend_scene_versions (task_id);

CREATE TABLE interference_frontend_scene_receipts (
    request_id VARCHAR(120) NOT NULL,
    request_digest VARCHAR(64) NOT NULL,
    actor_id VARCHAR(120) NOT NULL,
    task_id VARCHAR(120) NOT NULL,
    scene_id VARCHAR(120) NOT NULL,
    version_id VARCHAR(40) NOT NULL,
    receipt JSON NOT NULL,
    created_at DATETIME NOT NULL,
    PRIMARY KEY (request_id),
    FOREIGN KEY(task_id) REFERENCES planning_tasks (task_id),
    FOREIGN KEY(scene_id) REFERENCES interference_frontend_scenes (scene_id),
    FOREIGN KEY(version_id) REFERENCES interference_frontend_scene_versions (version_id)
);
CREATE INDEX ix_interference_frontend_scene_receipts_task_id
    ON interference_frontend_scene_receipts (task_id);
```

版本号/唯一回执由约束与事务保证；ORM 的 before_update/before_delete 拒绝修改版本和回执。最新指针归属、冻结内容哈希及引用由服务在读写时核验。SQLite 写入先 `BEGIN IMMEDIATE` 再读取来源；GET 使用显式只读事务保持分页计数与页面的一致时点，关闭时只回滚读事务。没有进程内缓存、工作区自动初始化或算法调用。
