# 3.2 CSCI能力需求

## 3.2.1 功能组成概述

本软件的能力需求用于规定短波/超短波智能规划系统软件配置项在验收时应具备的主要业务能力。根据[【非密】短波规划要求.docx](/e:/project2026-1/【非密】短波规划要求.docx)、[1111 2.docx](/e:/project2026-1/1111%202.docx)和[软件需求规格说明模板(1).docx](/e:/project2026-1/软件需求规格说明模板(1).docx)的相关要求，本软件能力主要由以下部分组成：

1. 全域资源统一管理
2. 设备孪生建模
3. 知识图谱构建与查询
4. 智能网络规划
5. 综合态势呈现
6. 故障智能诊断
7. 系统管理

## 3.2.2 全域资源统一管理能力

全域资源统一管理能力用于支撑短波、超短波和光纤网络相关资源的统一编目、统一查询、统一维护和统一展示，为后续设备管理、网络规划、态势呈现和故障诊断提供一致的数据基础。

### 分项需求说明

#### SR-3.2-001 全域资源统一管理能力

- 需求名称：全域资源统一管理能力
- 需求内容：软件应具备对短波、超短波和光纤网络相关设备、链路和站点资源进行统一管理的能力。
- 合格性方法：演示 / 审查
- 追踪来源：《【非密】短波规划要求》总体要求；《1111 2》建设目标

#### SR-3.2-002 资源分类管理能力

- 需求名称：资源分类管理能力
- 需求内容：软件应支持按站点、设备、链路和网络类型对资源进行分类管理。
- 合格性方法：演示 / 审查
- 追踪来源：《【非密】短波规划要求》总体要求；《1111 2》全域资源统一管理目标

#### SR-3.2-003 资源基础信息维护能力

- 需求名称：资源基础信息维护能力
- 需求内容：软件应支持对纳入管理范围的站点、设备和链路资源进行新增、修改、查询和停用处理。
- 合格性方法：演示 / 测试
- 追踪来源：《1111 2》全域资源统一管理目标

#### SR-3.2-004 统一资源查询能力

- 需求名称：统一资源查询能力
- 需求内容：软件应支持对纳入统一管理范围的资源进行统一查询，并返回与资源身份、所属网络、关联站点和关联链路相关的信息。
- 合格性方法：演示 / 测试
- 追踪来源：《1111 2》全域资源统一管理目标

#### SR-3.2-005 统一资源展示能力

- 需求名称：统一资源展示能力
- 需求内容：软件应支持在统一业务界面中展示短波、超短波和光纤网络相关资源信息，并为后续态势查看提供数据基础。
- 合格性方法：演示 / 审查
- 追踪来源：《【非密】短波规划要求》总体要求；《1111 2》建设目标

## 3.2.4 知识图谱构建与查询能力

知识图谱构建与查询能力用于支撑设备知识、网络态势知识和故障知识的组织、维护、查询和推理支撑。根据当前项目资料，自动抽取、命名实体识别和机器学习训练依赖语料条件，不作为本阶段无条件硬性能力。

### 分项需求说明

#### SR-3.2-011 三类知识图谱构建能力

- 需求名称：三类知识图谱构建能力
- 需求内容：软件应具备构建设备知识图谱、网络态势知识图谱和故障知识图谱的能力。
- 合格性方法：演示 / 审查
- 追踪来源：《【非密】短波规划要求》知识图谱功能；《1111 2》知识图谱构建目标

#### SR-3.2-012 设备知识维护能力

- 需求名称：设备知识维护能力
- 需求内容：软件应支持对设备工作原理、技术说明、使用维护信息和相关设备知识进行录入、更新和查询。
- 合格性方法：演示 / 测试
- 追踪来源：《【非密】短波规划要求》设备知识图谱功能；《1111 2》知识图谱需求

#### SR-3.2-013 网络态势知识维护能力

- 需求名称：网络态势知识维护能力
- 需求内容：软件应支持对组网规则、天线类型、网络角色、连接状态和信道质量相关知识进行维护和查询。
- 合格性方法：演示 / 测试
- 追踪来源：《【非密】短波规划要求》网络态势知识图谱功能；《1111 2》知识图谱需求

#### SR-3.2-014 故障知识维护能力

- 需求名称：故障知识维护能力
- 需求内容：软件应支持对故障现象、故障原因、故障部件、诊断步骤和解决方案相关知识进行维护和查询。
- 合格性方法：演示 / 测试
- 追踪来源：《【非密】短波规划要求》故障知识图谱功能；《1111 2》知识图谱需求

#### SR-3.2-015 知识查询能力

- 需求名称：知识查询能力
- 需求内容：软件应支持对设备知识、网络态势知识和故障知识进行查询，并返回与查询对象相关的知识结果。
- 合格性方法：演示 / 测试
- 追踪来源：《【非密】短波规划要求》知识图谱功能；《1111 2》知识图谱构建与查询功能

#### SR-3.2-016 推理支撑能力

- 需求名称：推理支撑能力
- 需求内容：软件应支持为网络规划和故障诊断提供基于知识组织结果的推理支撑能力。
- 合格性方法：演示 / 分析 / 审查
- 追踪来源：《1111 2》知识图谱构建目标；《五大模块技术详细方案》模块关系说明

#### SR-3.2-017 自动抽取能力待确认要求

- 需求名称：自动抽取能力待确认要求
- 需求内容：如需支持基于非结构化资料的自动知识抽取能力，软件应以甲方提供脱密资料和可用标注语料为前提；在相关资料未明确前，该能力不作为无条件验收要求。
- 合格性方法：审查
- 追踪来源：《半年落地问题清单》P-01；《五大模块技术详细方案》知识抽取部分

## 3.2 资料差异与待确认事项

### 资料差异

- 《【非密】短波规划要求》将知识图谱能力表述为“构建”功能，《五大模块技术详细方案》进一步展开到自动抽取、实体识别、关系抽取和图谱查询性能。本稿按最低验收口径保留“维护、导入、查询和推理支撑”能力，不将自动抽取默认写成硬性验收要求。
- 《【非密】短波规划要求》明确要求整合短波、超短波、光纤网络资源，但《半年落地问题清单》指出光纤网络与短波/超短波地图整合方式待确认。本稿保留统一管理能力，不扩写未明确的跨团队实现边界。
- 《【非密】短波规划要求》要求故障诊断场景不少于 3 类，而《1111 2》与《五大模块技术详细方案》出现了不少于 4 类场景或更复杂三层诊断结构的表述。本稿按最低验收口径保留基础故障诊断能力，不将更高场景数和机器学习诊断层直接写为硬性验收要求。
- 旧资料中曾出现短波不少于 10 个、超短波不少于 20 个、地图范围不小于 50 km × 50 km 的较低口径；当前上述指标已按用户确认口径统一调整为短波不少于 50 个、超短波不少于 100 个、地图范围不小于 120 km × 120 km，本稿据此执行。

### 待确认事项

- 设备状态上报接口协议和真实设备接入方式待确认。
- 知识图谱自动抽取所依赖的脱密资料和标注语料待确认。
- 光纤网络相关资源数据由哪一方提供、以何种边界接入待确认。
- 故障诊断场景的具体类别和覆盖边界待确认。
- 机器学习诊断能力是否纳入首期交付范围待确认。
- 国产化部署平台的 CPU 架构待确认。
