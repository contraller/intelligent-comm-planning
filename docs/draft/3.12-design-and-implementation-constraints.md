# 3.12 设计和实现约束
## 3.12.1 设计和实现约束概述

本章规定短波/超短波智能规划系统软件在设计、实现、集成、部署和验收过程中应遵守的约束条件。相关约束用于限定软件设计边界、实现选择、数据管理方式、接口处理规则和部署适配要求，以保证软件需求与项目资料、验收口径和实施风险控制要求保持一致。
本章描述的是约束条件，而不是详细技术方案。对于资料尚未明确的实现细节、协议细节、产品选型和资源规格，统一标注为“待确认”或“待设计阶段细化”，不将未确认技术路线直接写成强制验收要求。

### 分项需求说明
#### SR-3.12-001 约束范围定义要求

- 需求名称：约束范围定义要求
- 需求内容：软件应对设计、实现、集成、部署、运维和验收过程中需要遵守的约束条件进行定义，并与功能需求、接口需求、数据需求和资源需求保持一致。
- 合格性方法：审查
- 追踪来源：《软件需求规格说明模板(1).docx》3.12 章节说明；docs/draft/3.2-csci-capability-requirements.md；docs/draft/3.11-computer-resource-requirements.md

## 3.12.2 国产化适配约束

国产化适配是本项目已确认的约束方向，软件设计和实现应面向国产部署环境开展。

### 分项需求说明
#### SR-3.12-002 国产化部署适配要求

- 需求名称：国产化部署适配要求
- 需求内容：软件应支持在国产服务器、国产操作系统和国产数据库环境中部署运行。
- 合格性方法：演示 / 测试 / 审查
- 追踪来源：用户确认验收口径；docs/draft/3.2-csci-capability-requirements.md 3.2.9；docs/draft/3.11-computer-resource-requirements.md

#### SR-3.12-003 国产化选型待确认约束

- 需求名称：国产化选型待确认约束
- 需求内容：软件应将国产 CPU 架构、数据库类型和操作系统版本等选型差异纳入设计约束管理；具体选型结果待确认。
- 合格性方法：审查
- 追踪来源：《半年落地问题清单.docx》；skills/risk-scope-control.md

## 3.12.3 架构与模块化约束

软件应采用能够支撑主要业务模块解耦、协同和扩展的架构方式，避免将具体实现组件直接固化为需求主体。

### 分项需求说明
#### SR-3.12-004 模块化设计要求

- 需求名称：模块化设计要求
- 需求内容：软件应支持设备孪生建模、知识图谱构建、智能网络规划、综合态势呈现、故障智能诊断和系统管理等模块的职责划分和协同处理。
- 合格性方法：审查
- 追踪来源：skills/project-domain-knowledge.md；docs/draft/3.2-csci-capability-requirements.md

#### SR-3.12-005 模块边界一致性要求

- 需求名称：模块边界一致性要求
- 需求内容：软件应保持功能模块边界、内部接口定义和内部数据分类的一致性，不得在需求阶段混淆外部接口、内部接口和实现细节。
- 合格性方法：审查
- 追踪来源：docs/draft/3.3-software-external-interface-requirements.md；docs/draft/3.4-software-internal-interface-requirements.md；docs/draft/3.5-csci-internal-data-requirements.md

## 3.12.4 数据管理约束

数据管理约束用于保证资源、站点、链路、频率、图谱、故障和日志等数据在系统中的一致性、完整性和可追溯性。

### 分项需求说明
#### SR-3.12-006 数据一致性要求

- 需求名称：数据一致性要求
- 需求内容：软件应保证设备、站点、链路、频率、地图、知识图谱、故障诊断和日志等业务数据在相关模块之间保持一致。
- 合格性方法：审查
- 追踪来源：docs/draft/3.5-csci-internal-data-requirements.md；docs/draft/3.4-software-internal-interface-requirements.md

#### SR-3.12-007 数据完整性与追溯要求

- 需求名称：数据完整性与追溯要求
- 需求内容：软件应支持对关键业务数据、配置变更、诊断结论和重要操作记录进行完整性控制和追溯管理。
- 合格性方法：演示 / 审查
- 追踪来源：docs/draft/3.5-csci-internal-data-requirements.md 3.5.7、3.5.8、3.5.9

#### SR-3.12-008 数据保留周期约束要求

- 需求名称：数据保留周期约束要求
- 需求内容：软件应按甲方数据管理要求配置数据保留和清理策略；如原始资料未明确具体保留周期，不得在需求阶段自行设定固定期限。
- 合格性方法：审查
- 追踪来源：skills/srs-writing.md；skills/requirement-quality-review.md；docs/draft/3.5-csci-internal-data-requirements.md

## 3.12.5 GIS 地图与地形数据约束

GIS 地图与 DEM 地形数据是规划、覆盖分析和态势展示的基础资源，相关来源、授权和接入边界需在设计中保持受控。

### 分项需求说明
#### SR-3.12-009 地图范围支撑约束

- 需求名称：地图范围支撑约束
- 需求内容：软件应支持不小于 120 km × 120 km 范围的 GIS 地图显示、站点标绘、链路呈现和覆盖分析。
- 合格性方法：演示 / 测试 / 审查
- 追踪来源：用户确认验收口径；docs/draft/3.2-csci-capability-requirements.md 3.2.9

#### SR-3.12-010 地形场景支撑约束

- 需求名称：地形场景支撑约束
- 需求内容：软件应支持不少于 2 个地形地貌场景的数据使用和业务处理需求。
- 合格性方法：演示 / 测试 / 审查
- 追踪来源：《【非密】短波规划要求.docx》；docs/draft/3.2-csci-capability-requirements.md 3.2.9

#### SR-3.12-011 地图与地形数据来源约束

- 需求名称：地图与地形数据来源约束
- 需求内容：软件应对 GIS 地图数据来源、DEM 地形数据来源和相应使用授权进行约束管理；具体数据来源和授权边界待确认。
- 合格性方法：审查
- 追踪来源：docs/draft/3.3-software-external-interface-requirements.md 3.3.6、3.3.7；《半年落地问题清单.docx》

## 3.12.6 接口协议约束

接口协议约束用于保证外部接口和内部接口在设计与实现阶段具备可追踪、可联调和可验证的基础。

### 分项需求说明
#### SR-3.12-012 接口统一约束要求

- 需求名称：接口统一约束要求
- 需求内容：软件应对外部接口和内部接口采用统一、可追踪和可测试的接口约定方式。
- 合格性方法：审查
- 追踪来源：docs/draft/3.3-software-external-interface-requirements.md；docs/draft/3.4-software-internal-interface-requirements.md

#### SR-3.12-013 接口细节分阶段明确要求

- 需求名称：接口细节分阶段明确要求
- 需求内容：软件应在接口设计阶段进一步明确具体接口协议、字段、格式、调用顺序和异常处理细节；需求阶段不得编造未确认协议内容。
- 合格性方法：审查
- 追踪来源：skills/risk-scope-control.md；skills/requirement-quality-review.md

#### SR-3.12-014 设备与合作方接口边界约束

- 需求名称：设备与合作方接口边界约束
- 需求内容：软件应对真实设备接入方式、设备状态上报协议和光纤网络合作方数据边界进行约束管理；相关接口边界待确认。
- 合格性方法：审查
- 追踪来源：docs/draft/3.3-software-external-interface-requirements.md 3.3.4、3.3.5、3.3.11；《半年落地问题清单.docx》

## 3.12.7 安全与权限约束

安全与权限约束用于控制系统访问、重要操作和数据使用边界。

### 分项需求说明
#### SR-3.12-015 身份认证与权限控制要求

- 需求名称：身份认证与权限控制要求
- 需求内容：软件应支持用户身份认证、角色权限控制和按职责分配的业务访问约束。
- 合格性方法：演示 / 测试 / 审查
- 追踪来源：docs/draft/3.1-state-and-modes.md；docs/draft/3.2-csci-capability-requirements.md 3.2.8；docs/draft/3.3-software-external-interface-requirements.md 3.3.3

#### SR-3.12-016 审计记录约束要求

- 需求名称：审计记录约束要求
- 需求内容：软件应对登录、配置变更、数据导入导出、报告生成和重要业务操作保留审计记录。
- 合格性方法：演示 / 审查
- 追踪来源：docs/draft/3.2-csci-capability-requirements.md 3.2.8；docs/draft/3.5-csci-internal-data-requirements.md 3.5.8

## 3.12.8 性能指标约束

性能指标约束用于保证软件设计与实现满足当前确认的验收口径，而不将未确认的增强指标误写为强制要求。

### 分项需求说明
#### SR-3.12-017 节点规模约束要求

- 需求名称：节点规模约束要求
- 需求内容：软件应支持不少于 50 个短波节点和不少于 100 个超短波节点的资源管理、规划和态势呈现。
- 合格性方法：测试 / 分析 / 审查
- 追踪来源：用户确认验收口径；docs/draft/3.2-csci-capability-requirements.md 3.2.9

#### SR-3.12-018 规划预选配置约束要求

- 需求名称：规划预选配置约束要求
- 需求内容：软件应支持不少于 3 种规划预选配置。
- 合格性方法：测试 / 审查
- 追踪来源：《【非密】短波规划要求.docx》；docs/draft/3.2-csci-capability-requirements.md 3.2.9

#### SR-3.12-019 态势刷新约束要求

- 需求名称：态势刷新约束要求
- 需求内容：软件应满足不大于 1 分钟的态势刷新时间要求。
- 合格性方法：测试
- 追踪来源：用户确认验收口径；docs/draft/3.2-csci-capability-requirements.md 3.2.9

## 3.12.9 可扩展性约束

可扩展性约束用于控制系统在后续阶段扩展设备类型、知识内容、接口对象和故障场景时的可持续演进能力。

### 分项需求说明
#### SR-3.12-020 业务扩展支持要求

- 需求名称：业务扩展支持要求
- 需求内容：软件应支持设备类型、故障场景、地图图层、知识图谱内容和接口对象的后续扩展。
- 合格性方法：分析 / 审查
- 追踪来源：《五大模块技术详细方案.docx》；skills/project-domain-knowledge.md

## 3.12.10 第三方组件与开源软件约束

第三方组件和开源软件如被选用，应满足项目部署环境、安全审查和合规使用要求，但不在本章中将未确认组件直接指定为唯一实现方案。

### 分项需求说明
#### SR-3.12-021 第三方组件合规约束要求

- 需求名称：第三方组件合规约束要求
- 需求内容：软件应确保所使用的第三方组件或开源软件满足国产化部署、安全审查、许可合规和离线部署要求。
- 合格性方法：审查
- 追踪来源：skills/risk-scope-control.md；《半年落地问题清单.docx》

#### SR-3.12-022 未确认技术不得固化要求

- 需求名称：未确认技术不得固化要求
- 需求内容：软件应避免将未确认的第三方组件、算法名称、数据库产品或中间件产品直接固化为唯一实现要求。
- 合格性方法：审查
- 追踪来源：skills/srs-writing.md；skills/risk-scope-control.md

## 3.12.11 风险与待确认事项约束

本节汇总当前阶段仍需控制和确认的项目风险事项，以防止在需求阶段写入未经确认的实现承诺。

### 分项需求说明
#### SR-3.12-023 风险事项约束管理要求

- 需求名称：风险事项约束管理要求
- 需求内容：软件应将设备状态上报协议、真实设备接入方式、知识图谱语料、DEM 数据来源、国产 CPU 架构、光纤网络分工边界、ML 层是否纳入首期交付、文件导入导出格式和报告模板格式等事项作为待确认约束进行管理。
- 合格性方法：审查
- 追踪来源：《半年落地问题清单.docx》；docs/draft/3.3-software-external-interface-requirements.md；skills/risk-scope-control.md
